## Overview

TUI (REPL) mode requires a real terminal, so it cannot be launched directly through VS Code for debugging. Use **attach mode** to connect to a running Bun process.

## Procedure

### 1. Start the inspect service in a terminal

```bash
bun run dev:inspect
```

The command prints an address similar to `ws://localhost:8888/xxxxxxxx`.

### 2. Attach the VS Code debugger

1. Set breakpoints in files under `src/`
2. Press F5 → select **"Attach to Bun (TUI debug)"**

> **Note**: The WebSocket addresses in `dev:inspect` and `launch.json` change each time the process starts. Update both locations to keep them synchronized.

## How it works

The `dev:inspect` script actually runs `scripts/dev-debug.ts`:

```typescript
// scripts/dev-debug.ts
process.env.BUN_INSPECT = "localhost:8888/<token>"
await import("./dev")
```

Setting the `BUN_INSPECT` environment variable starts an inspect service compatible with the Chrome DevTools Protocol, then imports the dev-mode entry point. The VS Code `bun` extension attaches by connecting to the WebSocket address that the process prints.

## JetBrains IDEs

In principle, JetBrains IDEs (WebStorm / IntelliJ, and others) can also attach to the Bun inspect service (Run → Attach to Process), but this has not been verified. If you verify it successfully, please extend this documentation.

## Overview

Claude Code's GrowthBook system can connect to a custom GrowthBook server through environment variables, enabling remote feature-flag control.

- **When configured**: connect to your GrowthBook instance, then fetch and cache feature values
- **When not configured**: return each feature's default value from the code directly, without making network requests

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `CLAUDE_GB_ADAPTER_URL` | Yes | GrowthBook API URL, such as `https://gb.example.com/` |
| `CLAUDE_GB_ADAPTER_KEY` | Yes | GrowthBook SDK client key, such as `sdk-xxxxx` |

Adapter mode is enabled only when both variables are set. Otherwise, GrowthBook is skipped entirely.

## Usage

### Basic usage

```bash
CLAUDE_GB_ADAPTER_URL=https://gb.example.com/ \
CLAUDE_GB_ADAPTER_KEY=sdk-abc123 \
bun run dev
```

### Running without GrowthBook (default)

```bash
bun run dev
# Every getFeatureValue_CACHED_MAY_BE_STALE("xxx", defaultValue) call returns defaultValue directly
```

## GrowthBook server configuration

### Procedure

1. **Deploy a GrowthBook server**, either self-hosted with Docker or on GrowthBook Cloud
2. **Create an Environment**, such as `production`
3. **Create an SDK Connection** and obtain its SDK Key, which becomes `CLAUDE_GB_ADAPTER_KEY`
4. **Add Features as needed**, using the keys and types listed below

### Core principles

- **The application runs correctly with no configured features** because every call supplies a default value in code
- Create only the features that you want to control remotely; all others use their code defaults
- Once a feature is configured in GrowthBook, its value overrides the default in code

## Value-resolution precedence

Each feature value is resolved in the following order; the first match is returned:

```
1. CLAUDE_INTERNAL_FC_OVERRIDES environment variable (JSON object override)
   ↓ no match
2. growthBookOverrides configuration (~/.occ.json, ant builds only)
   ↓ no match
3. LOCAL_GATE_DEFAULTS (the local pins in growthbook.ts, which outrank any served value)
   ↓ no match
4. In-memory cache (remoteEvalFeatureValues, fetched from the server by this process)
   ↓ no match
5. The defaultValue argument supplied in code
```

## Caching and refresh behavior

| Mechanism | Description |
|---|---|
| **Disk cache** | **Removed** (2.45.0). The remote payload lives in memory only and is not persisted across processes |
| **Periodic refresh** | Fetches the latest values from the server automatically every 6 hours (`setInterval` + `unref`) |
| **Initialization timeout** | The first connection times out after 5 seconds, then uses the disk cache or default values |
| **Authentication changes** | Login and logout automatically destroy and recreate the client |

## Implementation details

The adapter changes 3 locations across 2 files:

1. **`src/constants/keys.ts`** — `getGrowthBookClientKey()` reads `CLAUDE_GB_ADAPTER_KEY` first
2. **`src/services/analytics/growthbook.ts`** — `isGrowthBookEnabled()` enables the adapter mode directly
3. **`src/services/analytics/growthbook.ts`** — the base URL uses `CLAUDE_GB_ADAPTER_URL` first

None of the 130+ caller files require changes.

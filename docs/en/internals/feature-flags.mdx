## What is `feature()`?

Claude Code uses the `bun:bundle` module from the Bun bundler for compile-time feature gating:

```typescript
// Usage in source code (src/tools.ts and elsewhere)
import { feature } from 'bun:bundle'

const RemoteTriggerTool = feature('AGENT_TRIGGERS')
  ? require('@open-claude-code/builtin-tools/tools/RemoteTriggerTool/RemoteTriggerTool.js').RemoteTriggerTool
  : null
```

In Anthropic's internal builds, `feature()` is evaluated during packaging. Code for which it returns `true` is retained; code for which it returns `false` is removed entirely through **dead code elimination (DCE)**.

In this decompiled version, `feature` is imported from `bun:bundle` (declared in `src/types/internal-modules.d.ts`) and always returns `false` at runtime:

```typescript
// src/types/internal-modules.d.ts
declare module 'bun:bundle' {
  export function feature(name: string): boolean;
}
```

As a result, code behind all 88+ feature flags **never executes at runtime**, but the code itself remains intact and available for inspection.

## Common patterns in the code

The codebase uses feature flags in three primary patterns.

### Pattern 1: load a tool conditionally

```typescript
// src/tools.ts — the most common pattern
const MonitorTool = feature('MONITOR_TOOL')
  ? require('@open-claude-code/builtin-tools/tools/MonitorTool/MonitorTool.js').MonitorTool
  : null
```

When the flag is `false`, DCE removes the `require()` call and the tool does not appear in the available-tool list.

### Pattern 2: register a command conditionally

```typescript
// src/commands.ts — slash-command registration
if (feature('VOICE_MODE')) {
  commands.push({ name: 'voice', description: '...' })
}
```

### Pattern 3: enable an API capability conditionally

```typescript
// src/constants/betas.ts — controls a beta header sent to the API
export const AFK_MODE_BETA_HEADER = feature('TRANSCRIPT_CLASSIFIER')
  ? 'afk-mode-2026-01-31'
  : ''
```

<Note>
Because `feature()` is evaluated at build time, code removed by DCE does not increase the final bundle size. In the decompiled version, all of this code remains present, which makes a complete analysis possible.
</Note>

## Notable findings

- The **KAIROS family** is the largest: 5 related flags control everything from core behavior to push notifications
- **`ABLATION_BASELINE`** supports scientific control experiments: it disables advanced features such as thinking, compaction, and auto-memory to measure the baseline performance of raw API calls
- **`ULTRAPLAN`** and **`ULTRATHINK`** suggest reasoning modes more advanced than the current extended-thinking capability

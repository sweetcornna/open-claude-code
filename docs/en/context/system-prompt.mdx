## From an array to an API call

The system prompt is not a fixed block of text. It is a **`string[]`** — the branded `SystemPrompt` type — assembled, split into blocks, and tagged for caching before it reaches the API.

### A three-stage pipeline

```
getSystemPrompt()            →  string[]         (assemble the content)
  ↓
buildEffectiveSystemPrompt() →  SystemPrompt     (pick the precedence path)
  ↓
buildSystemPromptBlocks()    →  TextBlockParam[] (split into blocks + cache_control)
```

1. **`getSystemPrompt()`** (`src/constants/prompts/assemble.ts`) collects the static and dynamic sections and inserts the `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` marker
2. **`buildEffectiveSystemPrompt()`** (`src/utils/session/systemPrompt.ts`) chooses among Override > Coordinator > Agent > Custom > Default
3. **`buildSystemPromptBlocks()`** (`src/services/api/claude.ts`) calls `splitSysPromptPrefix()` to split it and attaches `cache_control` to each block

## The branded type

```typescript
// packages/@ant/model-provider/src/types/systemPrompt.ts
export type SystemPrompt = readonly string[] & {
  readonly __brand: 'SystemPrompt'
}
export function asSystemPrompt(value: readonly string[]): SystemPrompt {
  return value as SystemPrompt  // zero-cost assertion
}
```

The brand prevents an ordinary `string[]` from being passed into an API call by accident — only an explicit `asSystemPrompt()` produces the type. `src/utils/session/systemPromptType.ts` is a backwards-compatibility re-export; the definition lives in the package above.

## The modular layout under `src/constants/prompts/`

`src/constants/prompts.ts` used to be a 900-line single file. It is now a **pure re-export barrel with no logic**, kept only so the dozen-odd existing import sites keep working. The prompt itself is split by concern into `src/constants/prompts/`, one module per section.

| File | What it holds |
|------|---------------|
| `assemble.ts` | `getSystemPrompt()`: section order, where the static/dynamic boundary goes, the two early-return paths (`CLAUDE_CODE_SIMPLE` and proactive), and `TOKEN_BUDGET_SECTION` |
| `shared.ts` | Strings more than one section needs verbatim: `SYSTEM_PROMPT_DYNAMIC_BOUNDARY`, `EMOJI_GUIDANCE`, `NO_COLON_BEFORE_TOOL_CALLS`, `SUMMARIZE_TOOL_RESULTS_SECTION` |
| `format.ts` | Rendering helpers: `prependBullets()` (the load-bearing ` - ` / `  - ` nesting) and `bulletSection()` (`# title` plus bullets, returning `null` when nothing survives) |
| `intro.ts` | The opening block, the cyber-risk instruction, the URL constraint. **The product identity line is not here** — `getCLISyspromptPrefix()` (`src/constants/system.ts`) prepends it |
| `harness.ts` | `# System`: facts about the harness the model cannot observe for itself (how its text reaches the user, the permission layer, core vs deferred tools, `<system-reminder>` tags, prompt injection, hooks) |
| `doingTasks.ts` | `# Doing tasks`: task scope, code style and comment discipline, faithful reporting, feedback channels |
| `actions.ts` | `# Executing actions with care`: reversibility and blast radius, the risk categories, the git pre-checks |
| `tools.ts` | `# Using your tools` plus `getAgentToolSection()`, and the two `CORE_TOOLS_PROMPT_*_NAMES` lists |
| `communication.ts` | `# Communicating with the user` — **user-facing text only** (updates between tool calls, the shape of the final answer, code-reference conventions) |
| `conduct.ts` | The conduct sections: `# Delivering work`, `# Corrections`, `# Context management`, plus three untitled standalone rules (pronoun default, task continuity, act-don't-re-derive) |
| `sessionGuidance.ts` | `# Session-specific guidance`: guidance that varies with what this session has available (must stay after the boundary) |
| `environment.ts` | `# Environment` and `computeSimpleEnvInfo()`, the knowledge-cutoff table, shell detection |
| `preferences.ts` | `# Language` and `# Output Style: <name>` |
| `mcp.ts` | `# MCP Server Instructions` (sorted by server name before joining) |
| `scratchpad.ts` | `# Scratchpad Directory` |
| `discoverSkills.ts` | The DiscoverSkills framing and its feature check, shared between the main session and subagents |
| `subagent.ts` | `DEFAULT_AGENT_PROMPT`, the subagent authority boundary, `enhanceSystemPromptWithEnvDetails()`. **Not part of `getSystemPrompt()`'s output** |
| `proactive.ts` | The whole autonomous-mode (proactive/KAIROS) skeleton and the `brief` section |

**Where to add things** — the three rules at the top of the barrel:

- a new prompt section → **its own module** under `./prompts/`
- ordering or the cache boundary → `./prompts/assemble.ts`
- a string two sections share → `./prompts/shared.ts`

`src/constants/prompts.ts` itself takes no logic any more.

> **Renamed sections.** What older docs called "Tone & Style" and "Output Efficiency" is now a single `# Communicating with the user`. The ant-only "Model Override" chain (`defaultSystemPromptSuffix`) has been deleted entirely, with a reverse assertion in the guardrail runner pinning that. There is no longer an "FRC" section.

## What `getSystemPrompt()` assembles, in render order

`getSystemPrompt()` returns an ordered array, joined with `\n\n`. The table below is the **actual render order**; re-derive it any time with `bun run scripts/dump-prompt.ts`, which writes the full output to `scripts/system-prompt-dump.txt` (gitignored — it is a script artifact, don't commit it).

"Untitled" entries genuinely carry no `#` heading. They are standalone one-rule blocks, not bullets inside a neighbouring section.

### The boundary marker

`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` (`= '__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__'`, defined in `shared.ts`) goes in right after item 13, and **only when `shouldUseGlobalCacheScope()` is true**. It is a sentinel string, stripped before the request is sent — the model never sees it. Its only job is to let the blocking logic mark exactly the static region as `scope: 'global'`.

### Dynamic region (after the boundary, via the section registry)

| # | Rendered heading | Module | Registry name |
|---|------------------|--------|---------------|
| 14 | `# Session-specific guidance` | `sessionGuidance.ts` | `session_guidance` |
| 15 | *(untitled)* memory-directory content | `src/memdir/memdir.ts` | `memory` |
| 16 | `# Environment` | `environment.ts` | `env_info_simple` |
| 17 | `# Language` | `preferences.ts` | `language` (null without a language preference) |
| 18 | `# Output Style: <name>` | `preferences.ts` | `output_style` |
| 19 | `# MCP Server Instructions` | `mcp.ts` | `mcp_instructions` (the only `DANGEROUS_uncached` one) |
| 20 | `# Scratchpad Directory` | `scratchpad.ts` | `scratchpad` |
| 21 | *(untitled)* token budget | `assemble.ts` | `token_budget`, requires the `TOKEN_BUDGET` feature |
| 22 | *(untitled)* brief mode | `proactive.ts` | `brief`, requires `KAIROS` or `KAIROS_BRIEF` |

Most dynamic sections are **conditional**. A dump taken with default settings renders the entire static region plus only `# Session-specific guidance` and `# Environment` — the rest return `null` and are filtered out because there is no language preference, no output style, no MCP server, no scratchpad, and the features are not compiled in.

## How static and dynamic are divided (and where occ diverges from upstream)

`assemble.ts` states two invariants in its JSDoc, both of which are easy to break silently:

1. **Everything before the boundary must be a build constant.** That prefix is hashed and cached *across organizations*. A section whose text varies with a runtime bit belongs after the marker, or it multiplies the cache-key variants by 2^N.
2. **Sections after the marker go through the section registry**, so they are memoized per conversation and invalidated on `/clear` and `/compact`.

**This is where occ deliberately diverges from upstream.** Upstream keeps the conduct sections (pronouns, `# Delivering work`, `# Corrections`, `# Context management`) in the dynamic half, because their gates read Anthropic A/B flags ANDed with a "is this a Claude model family" predicate. occ has **neither input** outside the first-party path, so porting the gates would silently blank those sections for most providers. occ therefore applies them **unconditionally** to every provider — which makes them build constants, which is why they sit in the cacheable half here. That is a deliberate divergence, not an oversight.

For the same reason `SUMMARIZE_TOOL_RESULTS_SECTION` — a plain constant string all along — now lives in the static region instead of occupying a dynamic slot.

Conversely, every condition inside `# Session-specific guidance` — the `enabledTools` set, `isForkSubagentEnabled()`, `getIsNonInteractiveSession()`, GrowthBook gate values — is a runtime bit and has to stay after the boundary. The source comment is blunt about it:

> Everything here must stay AFTER SYSTEM_PROMPT_DYNAMIC_BOUNDARY. Each conditional is a runtime bit that would otherwise multiply the Blake2b prefix-hash variants of the cacheScope:'global' prefix (2^N).

### The dynamic section registry

Dynamic sections register through `systemPromptSection()` or `DANGEROUS_uncachedSystemPromptSection()`, both defined in `src/constants/systemPromptSections.ts`:

```typescript
// Cached: computed once, recomputed only after /clear or /compact
systemPromptSection('memory', () => loadMemoryPrompt())

// Dangerous: recomputed every turn, which breaks the prompt cache
DANGEROUS_uncachedSystemPromptSection(
  'mcp_instructions',
  () => isMcpInstructionsDeltaEnabled() ? null : getMcpInstructionsSection(mcpClients),
  'MCP servers connect/disconnect between turns'  // a reason is mandatory
)
```

`resolveSystemPromptSections()` resolves every section each turn, preferring the cached value from `getSystemPromptSectionCache()` for anything with `cacheBreak: false`. MCP instructions are the only user of the dangerous variant in the whole prompt — and its gate check sits *inside* the compute function rather than selecting between two section variants, so a mid-session gate flip cannot read a stale cached value.

## Two early-return paths

`getSystemPrompt()` has two branches that never reach the table above.

### The `CLAUDE_CODE_SIMPLE` fast path

With `CLAUDE_CODE_SIMPLE` set, the whole prompt collapses to a single line:

```typescript
`You are Claude Code, Anthropic's official CLI for Claude.\n\nCWD: ${getCwd()}\nDate: ${getSessionStartDate()}`
```

Section registration, cache blocking, and dynamic assembly are all skipped. It exists for tests that need minimal token consumption.

### The proactive (autonomous) path

When `isProactiveActive()` is true the static skeleton is replaced wholesale: an agent driven by tick prompts has a different job shape than an interactive one, so it does **not** inherit `# Doing tasks` or `# Using your tools`. That path emits `PROACTIVE_INTRO` plus the cyber-risk instruction, the `<system-reminder>` explainer, `# Context management`, memory, environment, language, MCP instructions, scratchpad, the tool-result rule, and finally `# Autonomous work` from `getProactiveSection()`.

## Five levels of precedence

`src/utils/session/systemPrompt.ts` decides which prompt is actually used:

| Precedence | Condition | Behaviour |
|-----------|-----------|-----------|
| **0. Override** | `overrideSystemPrompt` is non-empty | Complete replacement; returns `[override]` |
| **1. Coordinator** | The `COORDINATOR_MODE` feature plus its environment variable | Uses the coordinator prompt |
| **2. Agent** | `mainThreadAgentDefinition` is present | In proactive mode it appends to the default; otherwise it replaces it |
| **3. Custom** | `--system-prompt` was passed | Replaces the default |
| **4. Default** | Nothing special | The full output of `getSystemPrompt()` |

`appendSystemPrompt` is always added at the end, except under Override.

## Providers

occ supports several API providers, in two groups:

| Group | Provider | Environment variable | Notes |
|-------|----------|---------------------|-------|
| **1P (first party)** | `firstParty` | default | Anthropic's API, direct |
| **3P** | `bedrock` | `CLAUDE_CODE_USE_BEDROCK=1` | AWS Bedrock |
| **3P** | `vertex` | `CLAUDE_CODE_USE_VERTEX=1` | Google Vertex AI |
| **3P** | `openai` | `CLAUDE_CODE_USE_OPENAI=1` | OpenAI compatibility layer (Ollama, DeepSeek, vLLM) |
| **3P** | `gemini` | `CLAUDE_CODE_USE_GEMINI=1` | Google Gemini |
| **3P** | `grok` | `CLAUDE_CODE_USE_GROK=1` | xAI Grok |

```typescript
// src/utils/model/providers.ts
export type APIProvider =
  | 'firstParty'
  | 'bedrock'
  | 'vertex'
  | 'foundry'
  | 'openai'
  | 'gemini'
  | 'grok'
```

**`getAPIProvider()` answers "which wire format", not "whose session this is."** Three different questions have three different predicates, and they must not be substituted for one another:

- `getAPIProvider()` — which wire protocol to speak
- `isThirdPartyModelCatalog()` — whose catalog and whose rate card; **this is what gates global caching**
- `servesAnthropicModels()` — whether the id `claude-opus-5` really means Anthropic's Opus 5; **this is what gates the model-catalog line in the environment section**

The provider also determines which beta headers are available (some are first-party-catalog only) and how tokens are counted (Bedrock has its own countTokens endpoint; OpenAI and Gemini fall back to estimation).

## Provider neutrality in the environment section

`# Environment` (`computeSimpleEnvInfo()`) is the only place in the prompt that states which model is running and what the machine looks like, which makes it the easiest place to tell a non-Anthropic session something false. Three gates:

- **The marketing name.** `getMarketingNameForModel()` returns `undefined` when the session does not serve Anthropic checkpoints, and the line renders as `You are powered by the model <id>.` — the bare id, no marketing name.
- **The Claude model-catalog line** ("Model IDs — Fable 5: …") is gated on **`servesAnthropicModels()`**. Not on `getAPIProvider()` (that answers which wire format) and not on `isThirdPartyModelCatalog()` (that answers whose rate card). Bedrock, Vertex and Foundry serve real Claude checkpoints and do want the line; an OpenAI-compatible endpoint resolves `claude-opus-5` to a literal string it does not serve, so handing that id to the model would be dictating a 404 into the user's code.
- **The fast-mode line** is gated on `isFastModeAvailable()`, which already folds in the third-party-catalog and subscription checks. Advertising a toggle the user cannot act on just produces a suggestion that goes nowhere.

The Anthropic product-lineup sentence (desktop app, web app, browser extension) is simply false for this build and has been **deleted**, with reverse assertions in the guardrail runner pinning it. Subagents go through `includeProductInfo: false` and get neither the catalog line nor the fast-mode line.

The knowledge-cutoff table (`getKnowledgeCutoff()`) is hand-maintained: upstream reads the model catalog's `knowledge_cutoff` field, and occ carries no such catalog data (`ALL_MODEL_CONFIGS` holds ids only).

## Caching: blocks, markers, and hits

This is the most intricate part of the design.

### The basics

Anthropic's prompt cache reuses an identical system prompt prefix across requests and bills cache hits at a fraction of the full input price. The cache key is a Blake2b hash of the content, so any character change invalidates it.

### `splitSysPromptPrefix()` and its three modes

`splitSysPromptPrefix()` in `src/utils/telemetry/api.ts` is the core of the caching strategy. It identifies the attribution header and the CLI prefix block by **content** (`CLI_SYSPROMPT_PREFIXES`) rather than by position.

**Mode 1 — MCP tools present (`skipGlobalCacheForSystemPrompt=true`)**

```
[attribution header]    → cacheScope: null    (uncached)
[system prompt prefix]  → cacheScope: 'org'
[everything else]       → cacheScope: 'org'
```

The MCP tool list can change mid-session as servers connect and disconnect, which undermines cross-organization caching, so it degrades to organization scope. The boundary marker is simply dropped on this path.

**Mode 2 — global cache with a boundary**

```
[attribution header]    → cacheScope: null    (uncached)
[system prompt prefix]  → cacheScope: null    (uncached)
[static content]        → cacheScope: 'global' (shared across organizations)
[dynamic content]       → cacheScope: null    (uncached)
```

This is the most efficient mode. Everything before `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` — the intro, `# System`, `# Doing tasks`, `# Communicating with the user`, the conduct sections — is identical for every user and can be cached globally.

> **When the boundary is inserted:**

```typescript
// src/utils/model/betas.ts
export function shouldUseGlobalCacheScope(): boolean {
  return (
    !isThirdPartyModelCatalog() &&
    !isEnvTruthy(process.env.CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS)
  )
}
```

```typescript
// src/constants/prompts/assemble.ts
...(shouldUseGlobalCacheScope() ? [SYSTEM_PROMPT_DYNAMIC_BOUNDARY] : []),
```

Which means:

- **Third-party-catalog sessions** (Bedrock, Vertex, Foundry, OpenAI, Gemini, Grok, OpenCode, …) never get a boundary and always run mode 3. Foundry is excluded because GrowthBook never bucketed Foundry users into the rollout experiment — the treatment data is first-party only.
- **Experimental betas disabled** (`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`) gets no boundary either
- **Everything else** gets the boundary and mode 2

Note the predicate is `isThirdPartyModelCatalog()`, not `getAPIProvider() === 'firstParty'` — a plain proxy or enterprise gateway serving `claude-*` models is not a third-party catalog and still gets global caching.

**Mode 3 — default (third-party catalog, or no boundary)**

```
[attribution header]    → cacheScope: null    (uncached)
[system prompt prefix]  → cacheScope: 'org'
[everything else]       → cacheScope: 'org'
```

### `getCacheControl()` and TTL

`getCacheControl()` in `src/services/api/claude.ts` produces the `cache_control` object:

```typescript
{
  type: 'ephemeral',
  ttl?: '1h',         // only for eligible query sources
  scope?: 'global',   // only the static region
}
```

`should1hCacheTTL()` decides the one-hour TTL:

- **Bedrock users** — enabled through `ENABLE_PROMPT_CACHING_1H_BEDROCK`
- **Explicit override** — `CLAUDE_CODE_PROMPT_CACHING_1H=1` opts an otherwise ineligible user (a bring-your-own API key, for instance) into the 1h TTL; `=0` forces 5m. **Both directions take precedence over the eligibility and allowlist checks below** — `=0` is the only way to switch off the 2× write surcharge on a metered key.
- **Eligibility** — internal users, or Claude subscribers not in overage (1h writes cost subscribers nothing extra)
- **Allowlist** — the `querySource` must match GrowthBook's `allowlist` array, which supports trailing wildcards such as `"repl_main_thread*"`. **When GrowthBook serves no config**, this falls back to `PROMPT_CACHE_1H_DEFAULT_ALLOWLIST` (`src/services/api/promptCacheTTL.ts`: main thread, compact, sdk, sub-agents). An explicitly served empty array still means "off for everyone", so the remote kill switch keeps working.
  - This previously fell back to `[]`, which made the 1h TTL dead code outside Anthropic's own deployment: **every pause longer than five minutes rewrote the entire 20–50K-token prefix**. Short-lived forked sources (`speculation`, `session_memory`, `prompt_suggestion`) are deliberately absent from the default list — they run 1–3 turns, so a 1h write is paid for and never read back.
- **Session stability** — the eligibility decision is latched in bootstrap state, so a mid-session GrowthBook change cannot produce inconsistent TTLs within one session

## Injecting context

The system prompt array carries no runtime context — no git state, no CLAUDE.md. Those arrive through two separate pipelines, both in `src/context.ts`.

### System context (`getSystemContext()`)

```typescript
export const getSystemContext = memoize(async () => {
  return {
    gitStatus,           // branch, status, recent commits
    cacheBreaker,        // only when BREAK_CACHE_COMMAND is compiled in
  }
})
```

- Memoized with `lodash.memoize`, so it is **computed once per session**
- The git snapshot runs five `git` commands in parallel (branch, defaultBranch, status, log, userName)
- Status beyond `MAX_STATUS_CHARS` (1000 characters) is truncated, with a note suggesting BashTool for more
- Git status is skipped entirely under `CLAUDE_CODE_REMOTE` or when git instructions are disabled
- `setSystemPromptInjection()` clears both the `getUserContext` and `getSystemContext` caches immediately

### User context (`getUserContext()`)

```typescript
export const getUserContext = memoize(async () => {
  return {
    claudeMd,            // merged CLAUDE.md content
    currentDate,         // "Today's date is YYYY-MM-DD."
  }
})
```

- CLAUDE.md is disabled by `CLAUDE_CODE_DISABLE_CLAUDE_MDS`, or by `--bare` unless a directory was named explicitly with `--add-dir`
- `--bare` means "skip what I did not ask for", not "ignore everything"

### Where each is injected

In `src/query.ts`:

```typescript
// system context is appended to the system prompt
const fullSystemPrompt = asSystemPrompt(
  appendSystemContext(systemPrompt, systemContext)  // simple concatenation
)
```

User context goes in through `prependUserContext()` (`src/utils/telemetry/api.ts`) as the first user message, wrapped in a `<system-reminder>` tag ahead of all conversation messages.

## The attribution header

The first block of every request's system prompt is the attribution header (`getAttributionHeader()` in `src/constants/system.ts`):

- **`cc_version`** — the occ version
- **`cc_entrypoint`** — which entry point is running (REPL, SDK, pipe, …; read from `CLAUDE_CODE_ENTRYPOINT`)
- **`cc_workload`** — a turn-scoped hint so the API can route e.g. cron-initiated requests to a lower QoS pool; absent means the interactive default
- **`cch=00000`** — when `NATIVE_CLIENT_ATTESTATION` is enabled, Bun's native HTTP layer replaces the zeros with a computed hash before sending, and the server verifies it to confirm a genuine client. The same-length placeholder is what avoids a Content-Length change and a buffer reallocation

The header is always `cacheScope: null` — it varies by version and entry point, so caching it would be pointless. `CLAUDE_CODE_ATTRIBUTION_HEADER=0` or a GrowthBook killswitch turns it off entirely.

## CLAUDE.md

Drop a `CLAUDE.md` in the project root and the model understands your project.

- **Overview** — what the project does, what it is built on
- **Conventions** — code style, naming, branching
- **Commands** — how to build, test, deploy
- **Gotchas** — known pitfalls, unusual configuration

Multiple levels are discovered and merged automatically:

```
~/.occ/CLAUDE.md                    ← user-global (personal preferences)
  └── /project/CLAUDE.md            ← project root (shared with the team)
        └── /project/src/CLAUDE.md  ← subdirectory (module-specific)
```

`getClaudeMds()` and `getMemoryFiles()` in `src/utils/session/claudemd.ts` walk up from the working directory and merge every match.

## Why `string[]` and not a single `string`

Modelling the prompt as an array exists for **cache blocking**:

1. Anthropic's prompt cache operates on **content blocks**
2. Splitting the prompt lets unchanging parts (the intro, `# System`) get their own cache hits
3. As one `string`, a single character change — a date rolling over — would invalidate the entire prompt's cache
4. The `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` marker lets `splitSysPromptPrefix()` mark exactly the static region as `scope: 'global'`, leaving the dynamic region uncached or at `scope: 'org'`

This is the central token-cost optimization: a typical system prompt runs 20K+ tokens, and cache blocking saves 30–50% of input token cost.

## Guardrails when editing the prompt

Three of them, and dropping any one leaves a class of change unobserved:

- **`bun run scripts/dump-prompt.ts`** renders the full prompt to `scripts/system-prompt-dump.txt` (gitignored — a script artifact, don't commit it). Running it before and after a change and diffing the two is the only way to see what the model actually receives: unit tests assert a handful of anchor sentences and cannot show section order, blank lines, or a whole section that got gated off. It takes an optional model id as its first argument.
- **`src/constants/promptEngineeringAudit.runner.ts`** holds behavioural anchors, reverse assertions for deleted content (the Anthropic product lineup, the ant-only `defaultSystemPromptSuffix`, …), and structural assertions (static section order; `# Session-specific guidance` and `# Environment` must not appear before the boundary).
- **`tests/mocks/systemPromptEnv.ts`** is the mock chain shared by the dump script and the guardrail runner. Every override there exists to make the output *deterministic* — independent of the host machine's provider config, git state, feature flags and terminal — not to stub something out. The two callers used to carry hand-written copies, which drifted.

## The OpenAI and Gemini compatibility layers

occ ships compatibility layers for the OpenAI, Gemini and Grok protocols, so non-Anthropic endpoints can be used. The code sits in two places: **protocol, auth and networking** under `src/services/api/<provider>/`, and **format conversion** under `packages/@ant/model-provider/src/providers/<provider>/`.

### OpenAI

Enabled with `CLAUDE_CODE_USE_OPENAI=1`. It is a **stream adapter**:

1. Convert the Anthropic-shaped request to OpenAI's shape
2. Call the compatible endpoint
3. Convert the SSE stream back into `BetaRawMessageStreamEvent`
4. Nothing downstream is aware any of this happened

```
src/services/api/openai/
├── client.ts             # client configuration
├── wireProtocol.ts       # picks between the chat and responses lines
├── requestBody.ts        # request body construction
├── responsesAdapter.ts   # Responses API adaptation (idle watchdog, proxy support)
├── retry.ts              # backoff retries
├── reasoning.ts          # reasoning / effort parameters
├── gptBehaviorPrompt.ts  # the GPT-family behaviour overlay
├── chatgptAuth.ts        # ChatGPT subscription auth
└── index.ts              # queryModelOpenAI()
```

Key environment variables: `CLAUDE_CODE_USE_OPENAI=1`, `OPENAI_API_KEY`, `OPENAI_BASE_URL` (default `https://api.openai.com/v1`), `OPENAI_MODEL`, `OPENAI_WIRE_API` (`chat` by default, or `responses`).

### Gemini

Enabled with `CLAUDE_CODE_USE_GEMINI=1`.

Key environment variables: `CLAUDE_CODE_USE_GEMINI=1`, `GEMINI_API_KEY`, `GEMINI_BASE_URL` (default `https://generativelanguage.googleapis.com/v1beta`), `GEMINI_MODEL`, and the per-tier `GEMINI_DEFAULT_SONNET_MODEL` / `GEMINI_DEFAULT_OPUS_MODEL`.

### Limitations of the compatibility layers

On a third-party catalog, some things are unavailable:

- **No exact token counting** — the system falls back to estimation, which shifts when auto-compaction fires
- **No global cache** — `shouldUseGlobalCacheScope()` returns false, leaving only `scope: 'org'`
- **Some betas unavailable** — anything depending on Anthropic-specific beta headers
- **No Claude model-catalog line** — `# Environment` will not hand out `claude-*` ids

For the configuration sources of truth, see `docs/zh/features/providers.md` and `docs/zh/features/model-settings.md`.

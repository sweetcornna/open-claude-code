## 从数组到 API 调用：System Prompt 的完整链路

System Prompt 在 occ 中不是一段写死的文本，而是一个 **`string[]` 数组**（品牌类型 `SystemPrompt`），经过组装、分块、缓存标记后发送给 API。

### 三阶段管道

```
getSystemPrompt()          →  string[]       （组装内容）
  ↓
buildEffectiveSystemPrompt() →  SystemPrompt   （选择优先级路径）
  ↓
buildSystemPromptBlocks()  →  TextBlockParam[] （分块 + cache_control 标记）
```

1. **`getSystemPrompt()`**（`src/constants/prompts/assemble.ts`）—— 收集静态段 + 动态段，插入 `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 分界标记
2. **`buildEffectiveSystemPrompt()`**（`src/utils/session/systemPrompt.ts`）—— 按 Override > Coordinator > Agent > Custom > Default 优先级选择
3. **`buildSystemPromptBlocks()`**（`src/services/api/claude.ts`）—— 调用 `splitSysPromptPrefix()` 分块，为每个块附加 `cache_control`

## SystemPrompt 品牌类型

```typescript
// packages/@ant/model-provider/src/types/systemPrompt.ts
export type SystemPrompt = readonly string[] & {
  readonly __brand: 'SystemPrompt'
}
export function asSystemPrompt(value: readonly string[]): SystemPrompt {
  return value as SystemPrompt  // 零开销类型断言
}
```

品牌类型（branded type）防止普通 `string[]` 被意外传入 API 调用——只有通过 `asSystemPrompt()` 显式转换才能获得 `SystemPrompt` 类型。`src/utils/session/systemPromptType.ts` 是向后兼容的再导出层，本体在上面那个 package 里。

## `src/constants/prompts/` 的模块化布局

`src/constants/prompts.ts` 曾是一个 900 行的单文件，现在只剩一个**纯再导出 barrel**（无逻辑），存在的唯一目的是让十几个既有 import 点继续工作。提示词本体按关注点拆到 `src/constants/prompts/` 下，一个段落一个模块。

| 文件 | 放什么 |
|------|--------|
| `assemble.ts` | `getSystemPrompt()`：段落顺序、静态/动态边界的位置、两条早退路径（`CLAUDE_CODE_SIMPLE` 与 proactive），以及 `TOKEN_BUDGET_SECTION` |
| `shared.ts` | 一个以上段落逐字共用的常量：`SYSTEM_PROMPT_DYNAMIC_BOUNDARY`、`EMOJI_GUIDANCE`、`NO_COLON_BEFORE_TOOL_CALLS`、`SUMMARIZE_TOOL_RESULTS_SECTION` |
| `format.ts` | 渲染 helper：`prependBullets()`（` - ` / `  - ` 两级缩进）与 `bulletSection()`（`# 标题` + bullet，全空则返回 `null`） |
| `intro.ts` | 开场白、网络风险指令、URL 约束。**产品身份行不在这里**——它由 `getCLISyspromptPrefix()`（`src/constants/system.ts`）前置 |
| `harness.ts` | `# System`：模型自己观察不到的 harness 事实（输出如何抵达用户、权限模式、核心工具 vs 延迟工具、`<system-reminder>` 标签、prompt injection、hooks） |
| `doingTasks.ts` | `# Doing tasks`：任务范围、代码风格与注释纪律、如实汇报、反馈渠道 |
| `actions.ts` | `# Executing actions with care`：可逆性与影响半径、风险动作分类、git 前置检查 |
| `tools.ts` | `# Using your tools` + `getAgentToolSection()`，以及 `CORE_TOOLS_PROMPT_*_NAMES` 两张核心工具名单 |
| `communication.ts` | `# Communicating with the user`：**只管用户可见文本**（工具调用之间的更新、最终回答的形状、引用代码的约定） |
| `conduct.ts` | 行为准则段落：`# Delivering work`、`# Corrections`、`# Context management`，以及三条无标题独立规则（代词默认、任务连续性、有信息就行动） |
| `sessionGuidance.ts` | `# Session-specific guidance`：随本次会话可用能力变化的指引（必须在边界之后） |
| `environment.ts` | `# Environment` + `computeSimpleEnvInfo()`、知识截止日期表、shell 探测 |
| `preferences.ts` | `# Language` 与 `# Output Style: <name>` |
| `mcp.ts` | `# MCP Server Instructions`（按服务器名排序后拼接） |
| `scratchpad.ts` | `# Scratchpad Directory` |
| `discoverSkills.ts` | DiscoverSkills 的措辞与 feature 判定，主会话与子 agent 共用 |
| `subagent.ts` | `DEFAULT_AGENT_PROMPT`、子 agent 授权边界、`enhanceSystemPromptWithEnvDetails()`。**不参与 `getSystemPrompt()` 的输出** |
| `proactive.ts` | 自主模式（proactive/KAIROS）的整套骨架与 `brief` 段落 |

**新增内容该往哪写**（barrel 顶部注释即是这三条）：

- 一个新的提示词段落 → `./prompts/` 下**自己的模块**
- 顺序 / 缓存边界的调整 → `./prompts/assemble.ts`
- 两个段落共用的字符串 → `./prompts/shared.ts`

`src/constants/prompts.ts` 本身不再接受任何逻辑。

> **段落改名提示**：旧文档里的「Tone & Style」与「Output Efficiency」已合并为单一段落 `# Communicating with the user`；ant-only 的「Model Override」（`defaultSystemPromptSuffix`）整条链已删除，护栏里有反向断言钉住；「FRC」段落已不存在。

## getSystemPrompt()：段落的真实渲染顺序

`getSystemPrompt()` 返回一个有序数组，最终以 `\n\n` 拼接。下表按**实际渲染顺序**列出，可用 `bun run scripts/dump-prompt.ts` 重新核对（它把完整输出写到 `scripts/system-prompt-dump.txt`，该文件已在 `.gitignore` 中，属脚本产物）。

「无标题」的条目是真的没有 `#` 标题——它们是独立成块的单条规则，不是某个段落的子项。

### 静态区（边界之前，可跨组织缓存）

| # | 渲染出的标题 | 源模块 | 产出函数 / 常量 |
|---|--------------|--------|-----------------|
| 1 | *（无标题）* 开场白 + 网络风险 + URL 约束 | `intro.ts` | `getIntroSection()` |
| 2 | `# System` | `harness.ts` | `getSystemSection()` |
| 3 | *（无标题）* 代词未声明时默认 they/them | `conduct.ts` | `getPronounsSection()` |
| 4 | `# Doing tasks` | `doingTasks.ts` | `getDoingTasksSection()`——output style 声明 `keepCodingInstructions: false` 时整段消失 |
| 5 | `# Executing actions with care` | `actions.ts` | `getActionsSection()` |
| 6 | *（无标题）* 任务连续性（已同意的任务覆盖到底） | `conduct.ts` | `getTaskContinuitySection()` |
| 7 | `# Using your tools` | `tools.ts` | `getUsingYourToolsSection(enabledTools)` |
| 8 | `# Communicating with the user` | `communication.ts` | `getCommunicationSection()` |
| 9 | `# Delivering work` | `conduct.ts` | `getDeliveringWorkSection()` |
| 10 | `# Corrections` | `conduct.ts` | `getCorrectionsSection()` |
| 11 | `# Context management` | `conduct.ts` | `getContextManagementSection()` |
| 12 | *（无标题）* 有足够信息就行动，不要重新推导已确立的事实 | `conduct.ts` | `getActNotRederiveSection()` |
| 13 | *（无标题）* 工具结果里的关键信息要写进回答 | `shared.ts` | `SUMMARIZE_TOOL_RESULTS_SECTION` |

### 分界标记

`SYSTEM_PROMPT_DYNAMIC_BOUNDARY`（`= '__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__'`，定义在 `shared.ts`）插在第 13 项之后，且**仅当 `shouldUseGlobalCacheScope()` 为真时才插入**。它本身是一个哨兵字符串，发送给 API 前被移除，模型永远看不到；作用是让分块逻辑精确地把静态区标成 `scope: 'global'`。

### 动态区（边界之后，走 Section 注册表）

| # | 渲染出的标题 | 源模块 | 注册名 |
|---|--------------|--------|--------|
| 14 | `# Session-specific guidance` | `sessionGuidance.ts` | `session_guidance` |
| 15 | *（无标题）* 记忆目录内容 | `src/memdir/memdir.ts` | `memory` |
| 16 | `# Environment` | `environment.ts` | `env_info_simple` |
| 17 | `# Language` | `preferences.ts` | `language`（未设置语言偏好时为 `null`） |
| 18 | `# Output Style: <name>` | `preferences.ts` | `output_style` |
| 19 | `# MCP Server Instructions` | `mcp.ts` | `mcp_instructions`（唯一的 `DANGEROUS_uncached`） |
| 20 | `# Scratchpad Directory` | `scratchpad.ts` | `scratchpad` |
| 21 | *（无标题）* token 预算 | `assemble.ts` | `token_budget`，需编译进 `TOKEN_BUDGET` |
| 22 | *（无标题）* brief 模式 | `proactive.ts` | `brief`，需编译进 `KAIROS` 或 `KAIROS_BRIEF` |

绝大多数动态段落是**条件性**的：一次默认配置的 dump 只会渲染出静态区全部条目加 `# Session-specific guidance`、`# Environment` 两段，其余因为没有语言偏好 / 没有 output style / 没有 MCP 服务器 / scratchpad 未启用 / feature 未编译而返回 `null` 被过滤掉。

## 静态 / 动态的划分依据（以及 occ 与上游的分歧）

`assemble.ts` 的 JSDoc 把两条不变式写在函数头上，两条都会被静默破坏：

1. **边界之前的一切必须是构建期常量。** 那段前缀会被哈希并**跨组织**缓存。一个文本随运行时 bit 变化的段落必须放到标记之后，否则缓存键的变体数量按 2^N 膨胀。
2. **边界之后的段落走 Section 注册表**，因而按会话记忆化，并在 `/clear` 与 `/compact` 时失效。

**这里有一处 occ 与上游的有意分歧。** 上游把行为准则类段落（代词、`# Delivering work`、`# Corrections`、`# Context management`）留在动态区，因为它们的门控要读 Anthropic 的 A/B flag，并与「这是不是 Claude 模型家族」的判定做与运算。occ 在第一方路径之外**两个输入都没有**——照搬门控会让这些段落对多数 provider 静默变成空白。所以 occ 把它们**无条件**应用到每个 provider，于是它们成了构建期常量，也就该待在可缓存的那一半里。

同理，`SUMMARIZE_TOOL_RESULTS_SECTION` 本来就是一个常量字符串，现在放在静态区，不再占用一个动态槽位。

反过来，`# Session-specific guidance` 里的每一个条件——`enabledTools` 集合、`isForkSubagentEnabled()`、`getIsNonInteractiveSession()`、GrowthBook 的 gate 值——都是运行时 bit，必须留在边界之后。源码注释写得很直白：

> Everything here must stay AFTER SYSTEM_PROMPT_DYNAMIC_BOUNDARY. Each conditional is a runtime bit that would otherwise multiply the Blake2b prefix-hash variants of the cacheScope:'global' prefix (2^N).

### 动态区的 Section 注册表

动态区通过 `systemPromptSection()` / `DANGEROUS_uncachedSystemPromptSection()` 注册，这两个工厂函数定义于 `src/constants/systemPromptSections.ts`：

```typescript
// 缓存式 Section：计算一次，/clear 或 /compact 后才重新计算
systemPromptSection('memory', () => loadMemoryPrompt())

// 危险：每轮重新计算，会破坏 Prompt Cache
DANGEROUS_uncachedSystemPromptSection(
  'mcp_instructions',
  () => isMcpInstructionsDeltaEnabled() ? null : getMcpInstructionsSection(mcpClients),
  'MCP servers connect/disconnect between turns'  // 必须给出破坏缓存的理由
)
```

`resolveSystemPromptSections()` 在每轮查询时解析所有 Section，对于 `cacheBreak: false` 的 Section，优先使用 `getSystemPromptSectionCache()` 中的缓存值。整份提示词里只有 MCP 指令用了 `DANGEROUS_uncached` 变体——而且门控判断放在 compute 函数**内部**（而不是在两个 section 变体之间做选择），这样会话中途翻转 gate 不会读到陈旧的缓存值。

## 两条早退路径

`getSystemPrompt()` 里有两条不经过上面那张表的分支。

### `CLAUDE_CODE_SIMPLE` 快速路径

当环境变量 `CLAUDE_CODE_SIMPLE` 为真时，整个 System Prompt 缩减为一行：

```typescript
`You are Claude Code, Anthropic's official CLI for Claude.\n\nCWD: ${getCwd()}\nDate: ${getSessionStartDate()}`
```

跳过所有 Section 注册、缓存分块、动态组装——用于最小化 token 消耗的测试场景。

### Proactive（自主模式）路径

`isProactiveActive()` 为真时，静态骨架被整体替换：一个由 tick 驱动的 agent 与交互式 agent 的工作形态不同，因此它**不继承** `# Doing tasks` / `# Using your tools`。这条路径产出的是 `PROACTIVE_INTRO` + 网络风险指令、`<system-reminder>` 说明、`# Context management`、记忆、环境、语言、MCP 指令、scratchpad、工具结果转述，最后接 `# Autonomous work`（`getProactiveSection()`）。

## buildEffectiveSystemPrompt()：五级优先级

`src/utils/session/systemPrompt.ts` 决定最终使用哪个 System Prompt：

| 优先级 | 条件 | 行为 |
|--------|------|------|
| **0. Override** | `overrideSystemPrompt` 非空 | 完全替换，返回 `[override]` |
| **1. Coordinator** | `COORDINATOR_MODE` feature + 环境变量 | 使用协调者专用提示词 |
| **2. Agent** | `mainThreadAgentDefinition` 存在 | Proactive 模式：追加到默认提示词尾部；否则：替换默认提示词 |
| **3. Custom** | `--system-prompt` 参数指定 | 替换默认提示词 |
| **4. Default** | 无特殊条件 | 使用 `getSystemPrompt()` 完整输出 |

`appendSystemPrompt` 始终追加到末尾（Override 除外）。

## Provider 系统概述

occ 支持多种 API 提供商，分为两大类：

| 类别 | Provider | 环境变量 | 说明 |
|------|----------|---------|------|
| **1P (First Party)** | `firstParty` | 默认 | Anthropic 官方 API 直连 |
| **3P (Third Party)** | `bedrock` | `CLAUDE_CODE_USE_BEDROCK=1` | AWS Bedrock 托管服务 |
| **3P** | `vertex` | `CLAUDE_CODE_USE_VERTEX=1` | Google Vertex AI |
| **3P** | `openai` | `CLAUDE_CODE_USE_OPENAI=1` | OpenAI 兼容层（Ollama/DeepSeek/vLLM） |
| **3P** | `gemini` | `CLAUDE_CODE_USE_GEMINI=1` | Google Gemini API |
| **3P** | `grok` | `CLAUDE_CODE_USE_GROK=1` | xAI Grok |

```typescript
// src/utils/model/providers.ts
export type APIProvider =
  | 'firstParty'
  | 'bedrock'
  | 'vertex'
  | 'foundry'
  | 'openai'
  | 'gemini'
  | 'grok'
```

**`getAPIProvider()` 答的是「协议」，不是「归属」。** 系统提示词里有三个不同的问题各有各的谓词，不能混用：

- `getAPIProvider()` —— 走哪条线格式
- `isThirdPartyModelCatalog()` —— 谁的目录 / 谁的价目表；**全局缓存的门控用的是这个**
- `servesAnthropicModels()` —— `claude-opus-5` 这个 id 是不是真指 Anthropic 的 Opus 5；**环境段的模型目录行用的是这个**

Provider 还决定了可用的 beta headers（部分仅限第一方目录）与 token 计数方式（Bedrock 有独立 countTokens 端点，OpenAI/Gemini 依赖估算）。

## 环境段的 provider 中立化

`# Environment` 段（`computeSimpleEnvInfo()`）是整份提示词里唯一会说出「你是哪个模型、这台机器长什么样」的地方，因此也是最容易对非 Anthropic 会话撒谎的地方。三处门控：

- **模型营销名**：`getMarketingNameForModel()` 在本次会话不服务 Anthropic checkpoint 时返回 `undefined`，此时渲染成 `You are powered by the model <id>.`（裸 id，无营销名）。
- **Claude 模型目录行**（「Model IDs — Fable 5: …」）按 **`servesAnthropicModels()`** 门控。不是 `getAPIProvider()`（那答的是线格式），也不是 `isThirdPartyModelCatalog()`（那答的是价目表）。Bedrock/Vertex/Foundry 服务的是真的 Claude checkpoint，需要这行；而 OpenAI 兼容端点会把 `claude-opus-5` 解析成一个它并不服务的字面量字符串——把那个 id 交给模型等于让它把必然 404 的 API 串写进用户代码。
- **Fast mode 行**按 `isFastModeAvailable()` 门控（其中已折入第三方目录与订阅判定）。一个用户按不动的开关广告给模型，只会变成用户无法执行的建议。

Anthropic 产品线那句（桌面端 / 网页端 / 浏览器插件）在 occ 里是假话，**已删除**，护栏中有反向断言钉住。子 agent 走 `includeProductInfo: false`，拿不到模型目录行和 fast mode 行。

知识截止日期表（`getKnowledgeCutoff()`）是手工维护的：上游从模型目录的 `knowledge_cutoff` 字段读，occ 不携带那份目录数据（`ALL_MODEL_CONFIGS` 只有 id）。

## 缓存策略：分块、标记、命中

这是 System Prompt 设计中最精密的部分。

### Anthropic Prompt Cache 基础

Anthropic API 的 Prompt Cache 允许跨请求复用相同的 System Prompt 前缀，按缓存命中量计费（远低于完整输入价格）。缓存键由内容的 Blake2b 哈希决定——任何字符变化都会导致缓存失效。

### `splitSysPromptPrefix()`：三种分块模式

`src/utils/telemetry/api.ts` 里的 `splitSysPromptPrefix()` 是缓存策略的核心，根据条件选择三种分块模式。它通过**内容**而非位置识别归因头与 CLI 前缀块（`CLI_SYSPROMPT_PREFIXES`）。

#### 模式 1：MCP 工具存在时（`skipGlobalCacheForSystemPrompt=true`）

```
[attribution header]    → cacheScope: null     （不缓存）
[system prompt prefix]  → cacheScope: 'org'    （组织级缓存）
[everything else]       → cacheScope: 'org'    （组织级缓存）
```

MCP 工具列表在会话中可能变化（连接/断开），破坏了跨组织缓存的基础，因此降级为组织级。边界标记在这条路径上被直接丢弃。

#### 模式 2：Global Cache + Boundary 存在

```
[attribution header]    → cacheScope: null     （不缓存）
[system prompt prefix]  → cacheScope: null     （不缓存）
[static content]        → cacheScope: 'global' （全局缓存！跨组织共享）
[dynamic content]       → cacheScope: null     （不缓存）
```

这是缓存效率最高的模式。`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 之前的静态内容（Intro、`# System`、`# Doing tasks`、`# Communicating with the user`、行为准则各段等）对所有用户相同，可跨组织缓存。

> **Boundary 插入条件**：`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 标记**仅在特定条件**下插入：

```typescript
// src/utils/model/betas.ts
export function shouldUseGlobalCacheScope(): boolean {
  return (
    !isThirdPartyModelCatalog() &&
    !isEnvTruthy(process.env.CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS)
  )
}
```

```typescript
// src/constants/prompts/assemble.ts
...(shouldUseGlobalCacheScope() ? [SYSTEM_PROMPT_DYNAMIC_BOUNDARY] : []),
```

这意味着：

- **第三方目录会话**（Bedrock/Vertex/Foundry/OpenAI/Gemini/Grok/OpenCode 等）：Boundary 永远不存在，始终使用模式 3。Foundry 被排除是因为 GrowthBook 从未把 Foundry 用户分进那个 rollout 实验，treatment 数据只有第一方的。
- **禁用实验性功能**：设置 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`，Boundary 不插入
- **其余情况**：Boundary 存在，使用模式 2（最高缓存效率）

注意判据是 `isThirdPartyModelCatalog()` 而不是 `getAPIProvider() === 'firstParty'`——纯代理 / 企业网关配 claude 系模型不算第三方目录，照样拿得到全局缓存。

#### 模式 3：默认（第三方目录 或 Boundary 缺失）

```
[attribution header]    → cacheScope: null     （不缓存）
[system prompt prefix]  → cacheScope: 'org'    （组织级缓存）
[everything else]       → cacheScope: 'org'    （组织级缓存）
```

### `getCacheControl()`：TTL 决策

`src/services/api/claude.ts` 的 `getCacheControl()` 生成 `cache_control` 对象：

```typescript
{
  type: 'ephemeral',
  ttl?: '1h',         // 仅特定 querySource 符合条件时
  scope?: 'global',   // 仅静态区
}
```

1 小时 TTL 的判定逻辑（`should1hCacheTTL()`）：

- **Bedrock 用户**：通过环境变量 `ENABLE_PROMPT_CACHING_1H_BEDROCK` 启用
- **显式覆盖**：`CLAUDE_CODE_PROMPT_CACHING_1H=1` 让不符合资格的用户（如自带 API key）也用 1h TTL，`=0` 则强制退回 5m。**两个方向都优先于下面的资格与 allowlist 判定**——`=0` 是给按量计费 key 关掉 1h 写入 2 倍加价的唯一开关。
- **资格**：ant 用户，或未超额的 Claude 订阅用户（订阅用户的 1h 写入不额外计费）
- **allowlist**：`querySource` 需匹配 GrowthBook 配置的 `allowlist` 数组，支持前缀通配符（如 `"repl_main_thread*"`）。GrowthBook **不下发该配置时**回退到 `PROMPT_CACHE_1H_DEFAULT_ALLOWLIST`（`src/services/api/promptCacheTTL.ts`：主线程 / compact / sdk / 子 agent）；显式下发空数组仍表示「全员关闭」，远端 kill switch 照常生效。
  - 早先此处回退到 `[]`，等于 1h TTL 对所有非 Anthropic 内部部署都是死代码：**每次超过 5 分钟的停顿都会整体重写 ~20–50K token 的前缀**。短命 fork 源（`speculation`、`session_memory`、`prompt_suggestion` 等）刻意不在默认表内——它们只跑 1–3 轮，1h 写入付了钱也读不回来。
- **会话级锁定**：资格判定结果在 bootstrap state 中缓存，防止 GrowthBook 配置中途变化导致同一会话内 TTL 不一致

## 上下文注入：System Context 与 User Context

System Prompt 数组本身不包含运行时上下文（git 状态、CLAUDE.md 内容）。上下文通过两个独立的管道注入，两者都在 `src/context.ts`。

### System Context（`getSystemContext()`）

```typescript
export const getSystemContext = memoize(async () => {
  return {
    gitStatus,           // git 分支、状态、最近提交
    cacheBreaker,        // 仅 BREAK_CACHE_COMMAND 编译进时存在
  }
})
```

- 使用 `lodash.memoize` 缓存——**整个会话期间只计算一次**
- Git 状态快照包含 5 个并行 `git` 命令（branch、defaultBranch、status、log、userName）
- `status` 超过 `MAX_STATUS_CHARS`（1000 字符）时截断，并附加提示改用 BashTool 获取更多信息
- `CLAUDE_CODE_REMOTE` 为真或关闭了 git 指令时，整段 git 状态跳过
- `setSystemPromptInjection()` 会立即清空 `getUserContext` 与 `getSystemContext` 两份缓存

### User Context（`getUserContext()`）

```typescript
export const getUserContext = memoize(async () => {
  return {
    claudeMd,            // 合并后的 CLAUDE.md 内容
    currentDate,         // "Today's date is YYYY-MM-DD."
  }
})
```

- **CLAUDE.md 禁用条件**：`CLAUDE_CODE_DISABLE_CLAUDE_MDS` 环境变量，或 `--bare` 模式（除非通过 `--add-dir` 显式指定目录）
- `--bare` 模式的语义是"跳过我没要求的东西"而非"忽略所有"

### 注入位置

在 `src/query.ts` 中：

```typescript
// System Context 追加到 System Prompt 尾部
const fullSystemPrompt = asSystemPrompt(
  appendSystemContext(systemPrompt, systemContext)  // 简单拼接
)
```

User Context 通过 `prependUserContext()`（`src/utils/telemetry/api.ts`）注入为 `<system-reminder>` 标签包裹的首条用户消息，放在所有对话消息之前。

## Attribution Header：计费与安全

每个 API 请求的 System Prompt 首块是 Attribution Header（`src/constants/system.ts` 的 `getAttributionHeader()`），包含：

- **`cc_version`**：occ 版本号
- **`cc_entrypoint`**：入口点标识（REPL / SDK / pipe 等，读自 `CLAUDE_CODE_ENTRYPOINT`）
- **`cc_workload`**：轮次级提示，供 API 把 cron 触发之类的请求路由到较低 QoS 池；不存在即交互式默认
- **`cch=00000`**（`NATIVE_CLIENT_ATTESTATION` 启用时）：Bun 原生 HTTP 层在发送前将零替换为计算出的哈希值，服务器验证此 token 确认请求来自真实客户端。用等长占位符替换是为了不改变 Content-Length、不触发缓冲区重分配

Header 始终 `cacheScope: null`——它因版本与入口点不同而变化，不适合缓存。`CLAUDE_CODE_ATTRIBUTION_HEADER=0` 或 GrowthBook killswitch 可整体关闭。

## CLAUDE.md：项目级知识注入

在项目根目录放一个 `CLAUDE.md` 文件，就能让模型"理解"你的项目：

- **项目概述**：这个项目做什么、用了什么技术栈
- **开发约定**：代码风格、命名规范、分支策略
- **常用命令**：怎么构建、怎么测试、怎么部署
- **注意事项**：已知的坑、特殊的配置

系统会自动发现并合并多级 CLAUDE.md：

```
~/.occ/CLAUDE.md                 ← 用户全局（个人偏好）
  └── /project/CLAUDE.md         ← 项目根目录（团队共享）
        └── /project/src/CLAUDE.md  ← 子目录（模块特定）
```

加载逻辑在 `src/utils/session/claudemd.ts` 中的 `getClaudeMds()` 和 `getMemoryFiles()` 实现——从 CWD 向上遍历目录树，合并所有匹配的 CLAUDE.md 文件内容。

## 设计洞察：为什么是 `string[]` 而非单个 `string`

将 System Prompt 设计为数组而非单段文本，是为了 **缓存分块**：

1. Anthropic Prompt Cache 以 **内容块**（TextBlock）为缓存单位
2. 将 System Prompt 拆为多个块，可以让不变的部分（Intro、`# System`）获得独立的缓存命中
3. 如果是单个 `string`，任何一个字符变化（如日期更新）都会导致整个 System Prompt 的缓存失效
4. `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 标记允许 `splitSysPromptPrefix()` 精确地将静态区标记为 `scope: 'global'`，动态区不标记或标记为 `scope: 'org'`

这是 token 成本优化上的核心设计——一次典型的 System Prompt 约 20K+ tokens，通过缓存分块可以节省 30–50% 的输入 token 费用。

## 改提示词时的护栏

三道，缺一道就会有一类改动无人发现：

- **`bun run scripts/dump-prompt.ts`** —— 渲染完整提示词到 `scripts/system-prompt-dump.txt`（gitignore 内，脚本产物，不要提交）。改前改后各跑一次并 diff，是唯一能看见「模型实际收到什么」的手段：单测只断言若干锚点句，看不出段落顺序、空行以及被门控掉的整段。可传模型 id 作为第一个参数。
- **`src/constants/promptEngineeringAudit.runner.ts`** —— 行为锚点断言 + 已删内容的反向断言（Anthropic 产品线、ant-only 的 `defaultSystemPromptSuffix` 等）+ 结构断言（静态段落顺序、边界之前不得出现 `# Session-specific guidance` / `# Environment`）。
- **`tests/mocks/systemPromptEnv.ts`** —— dump 脚本与护栏 runner 共用的 mock 链，作用是让输出**确定**（不随宿主机的 provider 配置、git 状态、feature flag、终端变化），而不是把东西 stub 掉。两边曾各自手抄一份并很快漂移。

## 兼容层：OpenAI 与 Gemini

occ 提供了 OpenAI、Gemini、Grok 协议的兼容层，允许使用非 Anthropic 端点。代码分两处：**协议/认证/网络那半边**在 `src/services/api/<provider>/`，**格式转换那半边**在 `packages/@ant/model-provider/src/providers/<provider>/`。

### OpenAI 兼容层

通过 `CLAUDE_CODE_USE_OPENAI=1` 启用。实现采用**流适配器模式**：

1. 将 Anthropic 格式请求转换为 OpenAI 格式
2. 调用 OpenAI 兼容端点
3. 将 SSE 流转换回 `BetaRawMessageStreamEvent`
4. 下游代码完全无感知

```
src/services/api/openai/
├── client.ts             # 客户端配置
├── wireProtocol.ts       # chat / responses 两条线的选择
├── requestBody.ts        # 请求体构造
├── responsesAdapter.ts   # Responses API 适配（空闲看门狗、代理接入）
├── retry.ts              # 退避重试
├── reasoning.ts          # reasoning / effort 参数
├── gptBehaviorPrompt.ts  # GPT 家族的行为 overlay
├── chatgptAuth.ts        # ChatGPT 订阅认证
└── index.ts              # 入口函数 queryModelOpenAI()
```

关键环境变量：`CLAUDE_CODE_USE_OPENAI=1`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`（默认 `https://api.openai.com/v1`）、`OPENAI_MODEL`、`OPENAI_WIRE_API`（`chat` 默认 / `responses`）。

### Gemini 兼容层

通过 `CLAUDE_CODE_USE_GEMINI=1` 启用。

```
src/services/api/gemini/           packages/@ant/model-provider/src/providers/gemini/
├── client.ts                      ├── convertMessages.ts  # 消息格式转换
├── oauthToken.ts                  ├── convertTools.ts     # 工具定义转换
├── antigravityWire.ts             ├── streamAdapter.ts    # 流适配
├── reasoning.ts                   ├── modelMapping.ts     # 模型名称映射
└── index.ts  # queryModelGemini() └── usage.ts / types.ts
```

关键环境变量：`CLAUDE_CODE_USE_GEMINI=1`、`GEMINI_API_KEY`、`GEMINI_BASE_URL`（默认 `https://generativelanguage.googleapis.com/v1beta`）、`GEMINI_MODEL`，以及按档位映射的 `GEMINI_DEFAULT_SONNET_MODEL` / `GEMINI_DEFAULT_OPUS_MODEL`。

### 兼容层的限制

使用第三方目录时，部分功能受限：

- **无精确 token 计数**：系统退回到近似估算，影响自动压缩触发时机
- **无全局缓存**：`shouldUseGlobalCacheScope()` 返回 false，只能使用组织级缓存 `scope: 'org'`
- **部分 beta 功能不可用**：依赖 Anthropic 特有 beta headers 的功能受限
- **无 Claude 模型目录行**：`# Environment` 段不会给出 `claude-*` 的 id 清单

配置真源见 `docs/zh/features/providers.md` 与 `docs/zh/features/model-settings.md`。

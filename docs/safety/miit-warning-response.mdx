# Claude Code 有安全问题 - 5 分钟切到 Open Claude Code

## 预警：Claude Code 官方版本有安全问题

> Open Claude Code 项目：[github.com/sweetcornna/open-claude-code](https://github.com/sweetcornna/open-claude-code)

2026 年 7 月，工信部 NVDB 预警：官方 Claude Code `2.1.91`（2026-04-02）至 `2.1.196`（2026-06-29）版本内置隐蔽监控，读取系统时区、代理地址判断是否与中国相关，在请求中隐写标记回传地域、身份标识等敏感信息。Claude Code 本身有文件读写、命令执行等高权限，企业核心代码、密钥、内网架构都可能受影响。阿里 7 月 3 日已将其列入高风险名单，7 月 10 日起全面禁用；腾讯、美团、京东等也在收敛外部 AI 模型调用。

官方随后发布了修复版本，但产品仍是闭源黑盒，用户无法直接检查网络行为和数据流向。Open Claude Code 是对官方 Claude Code CLI 的逆向工程与反编译复原版本：保留可审计的 TypeScript 源码，将遥测组件替换为空实现，并支持自托管关键基础设施。

完整的遥测通道、文件路径、端点和触发条件见[遥测与远程配置下发系统审计](../telemetry-remote-config-audit)。

## Open Claude Code 默认不启用遥测

### 1. 遥测组件已替换为空实现

Open Claude Code 将三类遥测组件替换成了空实现（empty implementations，见仓库 `CLAUDE.md` 的 Stubbed/Deleted Modules 表）：

| 组件 | 官方行为 | Open Claude Code |
| --- | --- | --- |
| Analytics（Datadog + 1P BigQuery） | 生产环境批量上报 `tengu_*` 系列事件 | 空实现，不上报 |
| GrowthBook 远程配置 | 启动即拉取，每 6h 刷新 | 空实现，不拉取 |
| Sentry 错误追踪 | 上报异常堆栈 | 空实现，不上报 |

因此，Open Claude Code 不会通过这些遥测组件向 `us5.datadoghq.com`、`api.datadoghq.com` 等端点发送数据。相关代码路径仍保留接口形态，但实际网络上报已移除。

其余通道（OpenTelemetry、Beta Session Tracing、Remote Managed Settings 等）仍保留，但需要显式配置才会启用：

| 机制 | 官方默认 | Open Claude Code |
| --- | --- | --- |
| OpenTelemetry | 需 `CLAUDE_CODE_ENABLE_TELEMETRY=1` | 同上，默认不启用 |
| Beta Session Tracing | GrowthBook gate 控制 | 对应 feature 默认关闭 |
| Remote Managed Settings | API key 用户可能拉取 | 未配置企业端点时不拉取 |
| Settings Sync | feature gate 控制 | 默认关闭 |

### 2. 源码可以自行审计

官方 Claude Code 是混淆后的单文件产物；Open Claude Code 保留完整 TypeScript 源码，可以直接检查网络请求和遥测调用：

```bash
# 查找所有对 Anthropic API 的请求
grep -rn "api.anthropic.com" src/ packages/

# 查找所有遥测事件
grep -rn "logEvent\|trackDatadogEvent\|logEventTo1P" src/

# 查找所有远程配置拉取
grep -rn "growthbook\|remoteManagedSettings\|settingsSync" src/
```

完整审计记录见[遥测与远程配置下发系统审计](../telemetry-remote-config-audit)，可以按源码逐项复核。

### 3. 关键基础设施可以自托管

| 组件 | 自托管方案 | 文档 |
| --- | --- | --- |
| Feature Flag 平台 | 自建 GrowthBook 实例 | [GrowthBook 适配器](../internals/growthbook-adapter) |
| 错误追踪 | 自建 Sentry 实例 | [Sentry 配置](../internals/sentry-setup) |
| 远程控制 | 自托管 Happy 服务端（`HAPPY_SERVER_URL`），occ 只作为 ACP agent | [Remote Control](../features/remote-control-self-hosting) |
| HTML Artifact 托管 | Cloudflare Worker + R2 | [Cloud Artifacts](https://github.com/sweetcornna/open-claude-code/blob/main/packages/cloud-artifacts/README.md) |
| API 端点 | 任意 Anthropic API 兼容服务 | `/login` 命令配置 |

### 4. 隐私环境变量仍可作为额外保险

```bash
# 禁用所有非必要网络（含自动更新、release notes 等）
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 occ

# 使用第三方提供商，绕过 Anthropic 直连
CLAUDE_CODE_USE_OPENAI=1 occ        # OpenAI 兼容协议
CLAUDE_CODE_USE_GEMINI=1 occ        # Gemini
CLAUDE_CODE_USE_GROK=1 occ          # Grok
CLAUDE_CODE_USE_BEDROCK=1 occ       # AWS Bedrock
```

`src/utils/privacyLevel.ts` 是集中控制点，定义 `default < no-telemetry < essential-traffic` 三个级别。

## 换到 Open Claude Code 不需要牺牲核心功能

Open Claude Code 保留权限系统、沙箱、Plan Mode、Auto Mode、MCP、Skills、Hooks、Computer Use、Chrome Use、Voice Mode 和内置工具，并在此基础上扩展了一组社区功能：

| 特性 | 说明 |
| --- | --- |
| Goal 持续驱动 | `/goal <objective>` 设定目标后跨轮推进，支持 token budget、完成/阻塞审计及 `pause`、`resume`、`continue`、`clear` |
| Artifacts | 将 HTML、看板和报告上传到公开 URL，支持 7/30 天自动过期和自托管 |
| Dynamic Workflow | `/ultracode` + `Workflow` 工具运行确定性 JS 编排，支持 journal 重放、token budget 和并发上限 |
| ACP | 接入 Zed 等支持 ACP 的客户端，支持会话恢复、Skills 和权限桥接 |
| Remote Control | Docker 自托管远程界面，可从其他设备查看和控制会话 |
| Langfuse | 记录 agent loop、模型调用和工具执行，可转为数据集 |
| Channels | MCP server 将飞书、Slack、Discord 等外部消息推入会话 |
| Web Search | 内置网页搜索，支持 Bing 和 Brave |
| Poor Mode | 关闭记忆提取和提示建议，减少并发请求 |
| `/dream` | 整理和优化记忆文件 |
| 自定义模型供应商 | 支持 Anthropic、OpenAI、Gemini、Grok 等兼容端点 |

完整清单见[全特性指南](../features/all-features-guide)。

## 非破坏性迁移到 Open Claude Code

Open Claude Code 使用独立的命令和配置命名空间：

| Open Claude Code | 官方 Claude Code |
| --- | --- |
| `occ` / `occ-bun` | `claude` |
| `~/.occ/` | `~/.claude/` |
| `~/.occ.json` | `~/.claude.json` |
| 项目内 `.occ/` | 项目内 `.claude/` |

两者可以安装在同一台机器上。迁移过程中不要删除或修改 `~/.claude`，也不要把 `claude` 命令覆盖成 `occ`；这样才能保留真正的环境隔离。

### 步骤 1：确认官方版本

```bash
claude --version
# 若版本在 2.1.91 ~ 2.1.196 之间，属于预警涉及区间
```

### 步骤 2：安装 Open Claude Code

#### 方式 A：npm 全局安装

```bash
npm i -g open-claude-code

occ --version      # 验证 Node.js 入口
occ-bun --version  # 验证 Bun 入口
occ update         # 后续更新
```

作为本文所述更名工作的一部分，ccb 时期的 `ccb` / `ccb-bun` 命令名已被完全废止，现仅提供 `occ` / `occ-bun`。

#### 方式 B：从源码构建

```bash
git clone https://github.com/sweetcornna/open-claude-code.git
cd open-claude-code

# 需要 Bun >= 1.3.11
bun install
bun run build:vite

node dist/cli-node.js --version
bun dist/cli-bun.js --version

# 可选：从当前源码目录全局安装
bun install -g .
occ --version
```

### 步骤 3：迁移已有配置

先预览，再执行迁移：

```bash
occ migrate --dry-run
occ migrate
```

会复制用户编写或安装的配置：

- `settings.json`
- `skills/`、`agents/`、`commands/`
- `output-styles/`、`workflows/`、`plugins/`、`rules/`
- 旧全局配置中的 MCP server 定义

不会复制凭据、会话历史、缓存、日志和 IDE 锁文件。迁移是幂等的，不覆盖 `~/.occ` 中已经存在的文件，并且对 `~/.claude` 全程只读。

### 步骤 4：重新登录或配置 API 端点

凭据不会迁移。首次运行 `occ` 后，在 REPL 输入 `/login`，选择需要的供应商：

| 选项 | 适用场景 |
| --- | --- |
| Anthropic Compatible | 第三方 Anthropic API 兼容服务 |
| OpenAI | Ollama、DeepSeek、vLLM 等 OpenAI 协议端点 |
| Gemini | Google Gemini |
| Grok | xAI Grok |

根据供应商填写 Base URL、API Key 和模型 ID。快速开始与字段说明见[项目 README](https://github.com/sweetcornna/open-claude-code#readme)。

### 步骤 5：处理受影响的官方安装

occ 已经可以独立使用。对仍处于受影响区间的官方 Claude Code，请按企业安全策略选择升级或卸载；这一步不会影响 `occ` 的安装和 `~/.occ` 配置。

```bash
# npm 安装的官方版本
npm rm -g @anthropic-ai/claude-code

# Homebrew 安装的官方版本（macOS）
brew uninstall claude-code
```

如果还要继续使用官方版本，请安装已修复版本，并保持 `claude` 与 `occ` 两个命令各自独立。

### 步骤 6：验证隔离与运行状态

```bash
# 两个命令互不覆盖
occ --version
command -v occ

# occ 的配置写入独立目录
ls -la ~/.occ

# 启动 Open Claude Code
occ
```

在另一个终端可以按需观察网络连接：

```bash
sudo lsof -i -n -P | grep -E "occ|claude"
```

使用 Anthropic 或第三方 API 时出现对应 API 连接是正常的；重点是确认没有意外的 Datadog 遥测连接，并核对实际使用的 API 域名。

# Changelog (English)

Release notes for open-claude-code (`occ`).

This is a translation of [`CHANGELOG.md`](CHANGELOG.md), which is the canonical
source and the only one the tooling parses. Keep the structure identical:
`## <semver> - <date>` headings, top-level `- ` entries, newest first.

## 2.40.0 - 2026-08-11

- **Web-search credentials are now pinned automatically — no more manual `S`.** The pinning mechanism introduced last release fixed search silently degrading after logout or a provider switch, but it only worked once discovered — and the degradation is precisely silent, so the moment to open the panel never announces itself. Sources holding a usable key in the environment are now pinned automatically at startup, when `/search-setting` opens, on `R`, and after a provider-wizard save; a rotated key is followed, and nothing is written when nothing changed (timestamp included). The automatic path inherits every existing refusal: credentials mirrored from another provider, codex keys aimed at unofficial endpoints, and the rest are never stored. `D` unpins and records that the source is not to be pinned again; `S` pins and restores the automatic behavior.
- **Search credentials from Google and ChatGPT logins survive logout.** The gemini (Antigravity/Google OAuth) and codex (ChatGPT OAuth) sources can run without any key at all — their credential is occ's own authorization file, which `/logout` deletes, degrading search silently in exactly the same shape as the key case. Pinning these sources now copies the authorization file (refresh token included) into a search-owned 0600 copy: logout still deletes the main login and the main loop genuinely signs out, while search keeps working through the copy and refreshes its own tokens — a refresh of the copy is written back to the copy, never resurrecting the account that was signed out. Logout states which search credentials were kept. The `search-credentials.json` format is unchanged; no migration needed.

## 2.39.0 - 2026-08-11

- **Fixed requests still going to the previous endpoint after a provider switch, recoverable only by logging out.** A few environment variables that mark the session type (such as OpenCode's login marker) could be left behind on a profile switch: the cleanup rule requires a variable's current value to still equal the old configuration's value — protection for settings you exported in your own shell — but these markers are written only by occ and read every time a client is built. Once stale, they silently rewrote the destination of every subsequent request while the configuration itself looked perfectly fine — models reported "unsupported", switching models changed nothing, and only `/logout` ended it, being the one path that clears them unconditionally. Profile switches now reclaim these markers directly; the protection rule for every other variable is unchanged.
- **Fixed unsupported-model errors being reported as expired credentials.** Some gateways wrap "this model is not supported" in an HTTP 401. occ used to look only at the status code, so it reported the login as invalid and steered users into reconfiguring the provider — when the key was in fact valid, and the gateway had to authenticate the request before it could look up the model and answer that way. The response body's error type now takes precedence over the HTTP status, and these errors point at the model rather than the credential.
- **Provider profiles now record each tier's thinking effort and context ceiling.** Profiles used to store only the endpoint and models, so switching back to a profile brought back its provider but kept the previous provider's tier settings — switch from a 1M-context, max-effort configuration to GPT and those numbers were applied as-is. The settings are now saved and restored with the profile, in the same write as the endpoint. Profiles saved before this release carry no such settings; activating one resets the tiers to that provider's factory defaults instead of inheriting the previous provider's, and a single `/provider save <same-name>` records the current settings.
- **Fixed the aggregated list repeating the current provider's models.** The comparison used to match model names one by one, but `/model`'s own list filters out image, audio, realtime and other non-conversational models, while the profile stores the API's full list — so exactly the filtered-out ones reappeared at the bottom, marked "selecting will switch providers", on the provider you were already using. The profile owning the current session no longer contributes any rows. A different provider serving the same model name is still listed with its owner.
- **The web-search codex source supports pinning an independent credential.** It was previously the only one of the four sources that could not be pinned — its authentication happens inside the request with no injection point, so allowing the pin would have shown a connected row that could never actually be used. The request layer now accepts a key-and-endpoint pair, bringing codex in line with the other three: logout and provider switches no longer affect it. The endpoint and key must be passed as a pair, with no fallback to the session's current endpoint, so a pinned credential is never sent to wherever the session points later.
- **Fixed some tools getting an entire request rejected in Gemini sessions.** Gemini requires a tool's top-level parameter schema to describe an object, and its API measurably rejects any structure that sets sibling fields alongside `anyOf` (a restriction absent from the official documentation). The Workflow tool and MCP-server union-typed parameters used to go out in exactly that shape. Schemas are now normalized structurally at the Gemini boundary, not special-cased by tool name — MCP schemas are not written by occ, so the same shape can reappear at any time. Runtime validation still uses the original schema, and Anthropic and OpenAI requests are byte-for-byte unchanged.
- **Fixed codex first-time login failing at the pairing-code step in `/search-setting`.** The panel used to say "open the link and enter the pairing code", which reads as one action; but the page redirects a signed-out browser into the sign-in flow first, and the form that accepts the code only exists after that round trip — first-time users typed their code into a login page. The flow is now presented as two steps and opens the browser automatically; the pairing code has its own display slot that other messages cannot overwrite (previously the only way to see it again was to cancel and restart, which voids the code), and the dash is called out as part of the code.

## 2.38.3 - 2026-08-11

- **Fixed OpenCode Console logins returning "Invalid API key" on every request.** A Console token belongs to the account, and the inference endpoint for it is published by the account API — a different endpoint from Zen and Go. occ had the address hard-coded to a product constant, so it sent the token somewhere that only accepts API keys. Measured with one token: the account-published address returns a normal completion, Zen returns 401. The endpoint, organization header and model list are now read from the account API and stored beside the account rather than beside the token, since the token refreshes hourly and storing them together would lose the address within the hour. Sessions upgrading from the broken build recover without signing in again. Separately, "this model is disabled for your organization" was being classified as an authentication failure and sent users to sign in again, when the credential was fine; it now names the model and points at `/model`.
- **Search credentials are stored independently and no longer lost on logout or provider switch.** Web search previously read its keys from the main provider's environment variables — the same ones logout clears and a provider switch overwrites wholesale — so search silently degraded to the keyless scraping path, with nothing to indicate why. Credentials now live in their own file (mode 0600, one entry per source) that neither logout nor a provider switch can reach. Users who pin nothing are unaffected and need no migration. A pinned credential is actually used rather than merely shown as configured, and it is captured from the current environment rather than typed, so no key is ever rendered. Logout keeps them and says which sources were kept.
- **The `/provider-settings` panel can now add, rename, and show the aggregate as a whole.** Adding a provider previously meant leaving the panel, going through login, and saving separately. It can now be done in place, alongside a view of what the aggregated list actually contains — how many models each profile contributes and which model names collide. Adding switches the current session, which is stated before anything is chosen; if the live configuration is not yet saved as a profile, you are offered the chance to save it first so switching back is one keystroke.
- **Fixed the aggregated list stacking duplicates of the provider already in use.** Deciding "this is the provider I am already on" relied on a pointer written only when a profile is switched by hand, which a session configured through login never has; and the comparison matched tier aliases against concrete model names, which are not the same kind of thing. Ownership is now determined from the configuration itself, and the comparison happens after resolving to concrete models. A different provider serving the same model name is still listed and tagged with its owner — that is not a duplicate.
- **Merged two pairs of near-identically named commands.** `/models-setting` and `/model-settings` become the latter; `/provider` and `/provider-settings` become the latter. Every former name is kept as an alias, so existing habits and scripts are unaffected. The merged `/model-settings` also works on sessions with no configurable provider, which previously reached a dead end.
- **Fixed Responses API sessions failing on every turn after the first few.** Reasoning summary items do not carry replayable content under some configurations, yet occ replayed them anyway, after which the server answered "item not found" for every subsequent turn. Also fixed: gateways that omit argument deltas or output indices lost tool-call arguments entirely, reasoning summary parts ran together without separation, and a rate limit that stated how long to wait was retried immediately regardless.

## 2.38.2 - 2026-08-11

- **Auto-update now races candidate registries before downloading, cutting an install from minutes to seconds.** Measured at the same moment, the official npm registry ran at 17 KB/s on some networks while a public mirror reached 1.1 MB/s — a 63× difference that made a full install take close to six minutes. More seriously, the install timeout was 120 seconds against a real install that takes 347, so it was being killed a third of the way through every time; the 10-second version-check budget was similarly tight (a cold check measured 8.85 s) and, on expiry, was read as "no update available" leaving only a debug line. occ now probes the candidates concurrently before downloading and uses the fastest, and both limits have been widened to match reality. A registry you configured yourself always wins and is never raced, and occ does not modify your npm or bun configuration — the mirror is passed per-invocation to occ's own update command. The chosen mirror must advertise the same package digest as the official registry or it is discarded; `OCC_UPDATE_REGISTRY=official` turns the behaviour off.
- **New local, offline voice input that needs no account.** Neither existing backend was reachable for most people: one requires a claude.ai OAuth token (API keys, Bedrock, Vertex, Foundry and third-party providers all fail the check), and the service the other depended on stopped responding. With `voiceProvider: 'local'`, occ downloads a recognizer and a model on first use and then runs entirely offline — no key, no quota, no outbound request. Recognition happens in a separate process, so occ's own memory footprint is unaffected. The default model covers Chinese, English, Japanese, Korean and Cantonese; for Chinese-only dictation `paraformer-zh-small` measured the same accuracy with substantially less memory and a smaller download.

## 2.38.1 - 2026-08-11

- **Fixed third-party endpoints returning 400 on every request when workflows are enabled.** The Workflow tool's parameter schema had `anyOf` at its top level rather than `type: "object"`. Anthropic accepts that shape; OpenAI's function-calling contract does not, and a strict compatible endpoint rejects the **entire request** — leaving sessions on GLM, Kimi, Qwen, DeepSeek's chat lane and OpenCode completely unusable. Tool schemas are now normalized to an object at the boundary where they go onto the OpenAI wire, with no special case for any tool name: schemas supplied by MCP servers are not authored by occ, so the same shape can arrive again at any time. Runtime validation is unaffected (the original schema still governs), and requests on the Anthropic lane are byte-identical.
- **Fixed one message being displayed as two.** Two independent causes. The background session-title generation treated a failure as "try again next turn", so against a provider that returns errors it degraded into one request per turn — which, on a per-request metered relay, reads as the same message being sent twice. Separately, the placeholder shown after submitting input appeared alongside the real message in sessions past 500 messages, and that rendering path is the default on Windows and Windows Terminal, as well as whenever reduced motion is enabled.
- **OpenCode login now verifies the credential before writing any configuration.** Every request the login makes either needs no credential or tolerates a bad one — the model list is public on both Zen and Go — so the first thing that ever really used the credential was the user's first message, which came back `Invalid API key` and looked like a provider outage. Both the device-code and API-key paths now probe the selected endpoint first. On refusal nothing is written at all, and the login screen names the product, the URL, and how to switch to the other option.
- **Every API error is now retried.** Authentication failures, invalid requests, billing and permission errors previously failed on sight. They now retry as well, on a single 250 ms path, so an error that certainly will not change still surfaces in under a second. A user cancellation is never retried, and content already shown is never replayed — the consumers downstream are append-only, so a replay would display it twice. `CLAUDE_CODE_RETRY_ALL_ERRORS=0` restores the previous fast-fail. Error categories were corrected at the same time: the same failure no longer reports a different category depending on the retry verdict.
- **The status list is easier to scan when several subagents run at once.** Subagent task descriptions are now 2-4 word imperative phrases — the text is rendered verbatim in that list, one line per agent.

## 2.38.0 - 2026-08-10

- **New OpenCode provider, connecting directly to the Zen gateway and to Go subscriptions.** One account sits behind two distinct products, and `/login` now lists both side by side: Zen is pay-as-you-go (61 models, including the full Claude line) and Go is a flat subscription (25 open coding models). Picking the wrong one surfaces as `Insufficient balance`, a message that explains nothing on its own, so each option states its endpoint and billing model up front. Credentials may be a Console device-code login or an API key; the two are equivalent for inference, and the free tier needs no account at all. The wire protocol follows the model family automatically: Claude models use the Anthropic Messages API, GPT and the o-series use the Responses API, and everything else uses Chat Completions. Access tokens live only in a 0600 credential file — never in `settings.json`, and never in a saved provider profile. A session currently speaks one protocol, so pinning tiers across families leaves one of them on the wrong lane.
- **New `/provider-settings` for configuring several providers at once, switching freely between them, and aggregating some of them into a single model list.** The panel lists each saved provider with its endpoint and model count: `Enter` switches, `Space` adds or removes it from the aggregate, and `R` refreshes its model list. Once aggregated, `/model` shows the union of those providers' models, tagging any id served by more than one (`gpt-5.4 (relay)`); selecting one switches the session to the provider that serves it. Aggregation applies to the model list, not to connections — a single provider still serves the session at any moment, and tier aliases and subagents move with it. The panel shows endpoints and whether a key is stored, never a credential itself. The existing `/provider save|use|list|delete` subcommands are unchanged.
- **Auto-update now installs in the background as soon as an update is found, instead of waiting for every session to exit.** Updates were previously queued and installed only when the last session exited, which in practice meant sitting in a session for half an hour and seeing nothing happen. Installing during a run was avoided for a concrete reason: occ is built as roughly 612 content-hashed modules loaded on demand across the whole life of a session, and `install -g` rebuilds the package directory, so every not-yet-loaded module of a running session disappears and the next load wedges the interface beyond recovery. Startup now hard-links the running files into a private directory and loads from there, so replacing the package directory no longer affects live sessions — and the install can therefore happen immediately: a check about 60 seconds after startup, a background install when a newer version exists, effective on restart, with only one installer running at a time. Hard links consume no extra disk, and a copy is used automatically when the target sits on another volume.
- **Logout also clears the per-tier model settings, fixing the previous provider's tier defaults leaking into the next setup.** Logout used to leave `settings.modelSettings` and the legacy `effortLevel` in place, even though those values are seeded from the model family of the provider being logged out of. Logging out of DeepSeek and configuring GPT therefore handed all four tiers DeepSeek's row — a 1M context window and `max` effort rather than the 272k and `xhigh` they should get — with the setup wizard presenting both numbers as if the user had chosen them.

## 2.37.0 - 2026-08-10

- **Logout resets the entire account plane again, fixing the inability to reconfigure afterwards.** Logout previously cleared only three Anthropic credential keys; third-party provider endpoints and keys all survived and were written back into the process environment on the next launch. `isAnthropicAuthEnabled()` therefore still classified the session as third-party, the onboarding wizard omitted its login step, and a logged-out user had no path back to configuration. On DeepSeek sessions logout was entirely ineffective: the in-memory mirror regenerated `ANTHROPIC_API_KEY` from the surviving `OPENAI_API_KEY`. Logout now clears all provider keys and `modelType`, removes ChatGPT and Antigravity OAuth credentials, and releases the DeepSeek mirror. MCP OAuth tokens, plugin secrets, and saved provider profiles are unaffected, and `occ auth logout` now matches `/logout`.
- **Logout clears the rejected custom API key list.** The "Detected a custom API key" dialog only appears for keys in the "new" state, its default option is No, and cancelling counts as No — so a single rejection previously locked out that key permanently, with no command able to restore it.
- **WebSearch has execution timeout protection, so a single stuck tool no longer blocks the session.** A tool may declare an explicit wall-clock limit and run under its own child cancellation controller; a timeout terminates only that tool and leaves the session intact. WebSearch defaults to 60 seconds, adjustable via `CLAUDE_CODE_WEB_SEARCH_TIMEOUT_MS` or disabled with `0`. Aggregated search now genuinely aborts each source lane when its grace period expires or the primary lane is cancelled, instead of leaving background branches still issuing requests.
- **Third-party search paths share the API error retry ladder.** Direct Anthropic, DeepSeek, and Gemini searches retry recoverable errors, while permanent 4xx responses (authentication, permission, invalid arguments) and user cancellation fail immediately. SDK-level retries on the Anthropic path are disabled to avoid compounding with this layer.

## 2.36.1 - 2026-08-09

- **Agent and Workflow handoffs and cancellation no longer cross wires.** Moving a foreground Agent into the background continues the same stream instead of launching a duplicate Agent; cancelling one Workflow agent terminates only that agent while siblings and later phases continue. Late background-task notifications return to the main session after an agent exits, and terminal RemoteAgent tasks evict themselves according to their lifecycle.
- **Background processes and connections now complete their cleanup.** Naturally completed Shell tasks unregister cleanup callbacks, ACP cancellation waits for the query generator's `return()`, and daemon sessions remove their managed logs on exit. Delayed events from an old WebSocket can no longer invalidate a newer connection.
- **Third-party streaming APIs now time out and terminate for the real reason.** Anthropic streams enable the idle watchdog by default, while Gemini has both connection and per-read timeouts. Gemini safety blocks and malformed tool calls preserve partial output and surface an explicit error. The Responses API no longer misreports content filtering or unknown termination reasons as output-token truncation, and sends reasoning effort only to models that actually support it.
- **Deferred tools, MCP, and teammate mailboxes stay current under concurrency.** Prefetched tool discoveries can be passed directly to ExecuteExtraTool, and later Anthropic requests retain the full deferred-tool list. Concurrent `tools/list_changed` refreshes cannot write data from an obsolete connection, and mailbox polling no longer deletes messages that arrived after its snapshot.
- **Providers, profiles, and model settings no longer leak into one another.** Cross-tier Agents read effort and context from the slot that actually selected their model. Provider-profile switches fully clear stale model metadata while preserving environment values supplied by the shell or overwritten later by the user. Anthropic-compatible endpoints configured only through tiers use a third-party catalog, and explicit `FEATURE_*=0/false` opt-outs remain effective in Bun builds.
- **Migration and list UI behavior are safer under races and resizing.** Migration execution uses no-clobber semantics and will not merge into or overwrite destination files and directories that appeared after planning. When terminal height changes, CustomSelect immediately recomputes its visible window and keeps the current item on screen.

## 2.36.0 - 2026-08-09

- **Subscription sessions report a rate limit immediately instead of sitting through a pointless retry countdown.** A 429 on a Claude subscription (Max/Pro) now reads the server-provided reset time first and shows "rate limit reached" together with the recovery time, where it previously took a roughly 10-minute retry countdown to reach the same answer. The rule applies to every provider: retrying stops as soon as the server-stated reset window exceeds the per-attempt backoff cap, and the existing subscription retry contract is preserved when the server provides no such window. Both OpenAI wire protocols follow the same decision.
- **Configuration errors fail immediately with actionable guidance.** Permanent errors raised by occ itself — a ChatGPT subscription that is not logged in, Antigravity without an initialized project — no longer enter the retry ladder and state what needs fixing right away, instead of producing the same message about two minutes later.
- **Background requests no longer amplify retry storms during capacity overload (529).** Auxiliary background requests such as title generation and classifiers give up and are recorded on 529, leaving the retry budget to user-visible foreground requests.
- **API error messages now carry structured diagnostics.** Non-standard failures are converted into one consistent error message annotated with provider, HTTP status, error category, and retryability, making it easy to tell a misconfiguration from a transient fault.
- **Fixed three auto-update failures.** With `autoUpdates` disabled or `DISABLE_AUTOUPDATER=1` set, a previously queued deferred install no longer runs on exit; scripted `occ -p` invocations only register the session and never spawn a global install; session leases now also record the process start time, so a recycled pid can no longer stall auto-update permanently and silently.
- **ultracode is now a real switch.** While the mode is off, the model no longer receives ultracode or multi-agent orchestration prompting, and the Workflow tool carries an explicit opt-in threshold. Invoking `/ultracode` still works as a one-shot opt-in scoped to the current task, and toggling the mode mid-session takes effect immediately.
- **Fixed duplicate messages appearing after compaction in long sessions.** History replayed after a compact is merged by unique id, so the same entry is no longer displayed twice.

## 2.35.2 - 2026-08-09

- **Completed error classification and replay-safe retry boundaries across Anthropic Messages, OpenAI Chat/Responses, Gemini, and Grok.** HTTP status, provider `type/code/status`, network errno, and SSE error envelopes now share one classifier; 408/409/425/429/529, 5xx, connection failures, and temporary unavailability retry within the existing cap, while authentication, permission, billing, invalid requests, model-not-found, deterministic TLS failures, and user cancellation fail immediately. Responses now handles standard `event: error`, top-level `error`, and `response.error/failed`; Chat/Grok/Gemini/Responses no longer accept a truncated stream without its protocol terminal marker. Replay is allowed only before observable output: text, thinking, signatures, tool identity/arguments, or a refusal commit the attempt. SDK/NDJSON `error` remains a valid enum, while the original producer error is retained only as non-enumerable metadata.
- **Login, refresh, and logout no longer delete or lose credentials owned by other providers.** Replacement Anthropic credentials are made durable before the old API key/OAuth state is retired; macOS Keychain writes upsert directly instead of deleting first, and a failed deletion no longer reports logout success. A normal Anthropic logout removes only Anthropic credential fields and preserves ChatGPT/Codex, Gemini/Antigravity, MCP/plugin secrets, other API keys, provider profiles, model/endpoint settings, and Web Search configuration. Fallback secure storage reports success only after ensuring that an old primary value cannot shadow the fresh fallback.
- **Credential files now use atomic 0600 replacement, and Web Search setting failures are shown honestly.** ChatGPT, Antigravity, and plaintext secure-storage fallback write a same-directory temporary file, fsync it, and rename it; a failed atomic replacement never falls back to truncating the destination. `/search-setting` patches only the selected source override, and a failed write no longer flips the checkbox optimistically or displays success.
- **Fixed SSH reconnect and LSP lifecycle races that could leave unmanaged processes.** An SSH reconnect that completes after the user disconnects is terminated immediately; concurrent first requests for one LSP server share one start. Once shutdown begins, new initialize/start calls are rejected, while already registered starts are awaited and stopped again so a process cannot come alive after the manager has been cleared.
- **Workflow selection now stays visible in narrow and short terminals.** Phase and agent lists navigate independently according to focus; the selected agent cannot move into a clipped region, and pagination hints no longer cover the selected row. The active run tab rotates to the left edge of the visible window and tabs are capped by the panel's real display width. `Tab`/`Shift+Tab` switches panes; `[`/`]` switches runs.
- **Long-running background state and session cleanup no longer grow without bound or leave blank UI.** Long-running RemoteAgent tasks retain the latest 200 events while continuing to track the total count, todo state, and rich result; `cleanupPeriodDays` recursively cleans `tool-results` and `subagents` and refuses symlinks at every level. If a teammate exits while its details are open, TeamsDialog returns to the member list instead of leaving an empty modal.
- **Disabling one half of the deferred-tool gateway no longer makes every deferred tool disappear.** Schemas are deferred only when both SearchExtraTools and ExecuteExtraTool are available. If permissions remove either endpoint, occ no longer advertises an unusable search path and sends the remaining MCP/deferred tool schemas directly so they remain callable.

## 2.35.1 - 2026-08-08

- **Fixed a latent race where the background Bedrock inference-profile lookup could poison the global model-string cache.** The lookup is fired without being awaited, so its result could land seconds later in a cache that no longer belonged to a Bedrock session; the cache is only re-derived while empty, making one stale write permanent — every subsequent default-model resolution returned `us.anthropic.*`-style ids. Writes are now discarded unless the session is still Bedrock and the cache is still empty.
- **Test suite: eliminated cross-file env/module-cache leaks across 18 test files (the source of order-dependent Linux CI failures); Bedrock tests no longer make real AWS calls.** A module-level injection point now lets tests replace the inference-profile lookup without any `mock.module`.

## 2.35.0 - 2026-08-08

- **New independent `default` slot in model settings.** The provider default model configures effort and context independently from the haiku/sonnet/opus/fable tiers, even when they resolve to the same model id; explicit model ids always pass through unchanged. Factory defaults are now: GPT (incl. o-series) xhigh·272K, DeepSeek max·1M, Claude Opus/Fable xhigh·1M, Claude Sonnet/Haiku xhigh·200K, Gemini/Grok high·200K. Existing "Default"-row tier settings migrate to the `default` slot on upgrade from 2.34.
- **`/models` renamed to `/models-setting` (the provider HTTP `GET /models` endpoint is unchanged).** Saving awaits all side effects and applies to the current session immediately, no restart required; the Claude.ai, ChatGPT-subscription and Antigravity login flows apply immediately as well. ChatGPT-subscription and Antigravity sessions edit models and tier mappings only; credentials and login state are untouched. The model picker lists only models actually served by the endpoint, with built-in catalogs as fallback on official endpoints only; reopening the OpenAI form preserves `OPENAI_WIRE_API`.
- **Recoverable API errors retry uniformly, capped at 10 attempts.** Network drops, 429, transient 5xx, statusless upstream failures and Responses idle timeouts before first output all retry; auth, permission, invalid-request, model-not-found and user cancellation fail immediately. `Retry-After` is capped at 60s and backoff at 32s per attempt; SDK-level retries are disabled to prevent amplification; requests are never replayed once text/thinking/signature/tool output has been committed. Exceptions: 429s on Claude subscriptions (Max/Pro) are not retried (quota recovers on a time window); `CLAUDE_CODE_UNATTENDED_RETRY` changes from unlimited to the same cap of 10.
- **Agents and Workflow sub-agents share an execution watchdog.** 40 minutes (default) without tool output terminates the agent; placeholder output does not count as progress and active Bash/MCP/tool calls pause the timer; the total-runtime limit is off by default. Tune with `CLAUDE_CODE_AGENT_NO_PROGRESS_TIMEOUT_MS` and `CLAUDE_CODE_AGENT_TOTAL_TIMEOUT_MS` (0 disables). Terminated agents keep partial output and report a clear reason. Blank or thinking-only responses are no longer treated as success — including in the main session, they surface as model errors.
- **The main agent can query and control workflows.** Status includes run/phase/sub-agents/progress/token stats/failure reason and the run directory; resume supports checkpoint, all, an agent range or an explicit id list; runs are single-flight per runId and stale generations cannot overwrite newer ones.
- **Workflows and background tasks share one fixed-size panel.** `/workflows` and the task entry render the same view and layout no longer varies with content; `↑/↓` selects, `x` cancels the selected agent or the whole run; the separate `K` shortcut is removed.
- **Live MCP tool pool.** SearchExtraTools and Execute read the live pool on every call, including inside sub-agents; dynamic registration, removal and `tools/list_changed` take effect within the same turn. A failed first `listTools` is no longer cached as an empty result and the server is clearly shown as failed; one malformed tool no longer hides its siblings; a reconnected server never reuses stale schemas.
- **Chrome MCP is no longer bundled.** The `chrome-devtools-mcp` dependency, default server, CLI flags, `/chrome`, skill, settings and doctor entries are removed. Users who had enabled the built-in `mcp-chrome` must re-add it as a regular MCP server; any browser MCP can be configured normally.
- **Interactive sessions default to permission mode `auto` when nothing is configured.** `-p`/headless sessions keep `default`; explicit CLI/settings configuration always wins. Compact summaries no longer carry one-shot orchestration instructions into subsequent turns.
- **Unified provider URL construction.** No duplicated version segments, multi-segment custom base paths are preserved, and model-catalog requests target the correct endpoint. The Antigravity base-URL override moved from `GEMINI_BASE_URL` to a dedicated `ANTIGRAVITY_BASE_URL`; update existing proxy configurations accordingly.
- **Fixed Bing search results disappearing a full page at a time.** When Bing's click-tracking wrapper used a relative path, results were dropped before unwrapping; both forms are now unwrapped to the real address first.
- **Brave and Exa with a configured key join multi-source search automatically.** Like the logged-in official sources: present with a key, absent without one, and can be disabled in `/search-setting`; pinning the search backend exclusively is no longer required.

## 2.34.0 - 2026-08-07

- **Fixed long sessions that run subagents continually growing in memory until the entire process crashed.** The symptom was `FATAL ERROR: Ineffective mark-compacts near heap limit`; one observed crash reached 4GB. Every message produced by every subagent remained in the parent session forever — one real session ran 216 subagents, and one of those produced 1,270 messages by itself. A subagent's progress trace is now pruned when it finishes, retaining only its last few entries. Running agents are completely unaffected, and short agents lose nothing; the full pruned content already lives in `subagents/agent-<id>.jsonl`. Set `CLAUDE_CODE_AGENT_PROGRESS_RETAIN` to adjust how many entries are retained.
- **A diagnostic log is now recorded when memory crosses 1.5 / 2.5 / 3.5GB**, including usage, growth rate and elapsed runtime — the rate is what tells you whether memory is leaking. The switch for this automatic diagnostic existed before, but nothing ever invoked it, so the crash above left no clues. Set `CLAUDE_CODE_AUTO_HEAP_DUMP=1` to capture heap snapshots as well (off by default: a multi-GB heap produces an equally large file and stalls the process for several seconds).
- **Fixed a server process and its tools remaining available after the server was removed from `.mcp.json`.** Previously only plugin-sourced servers were reclaimed, not servers from `.mcp.json`; file changes also triggered no rescan, so a restart or `/clear` was required. Changes to `.mcp.json` now take effect within the session, and a removed server is reclaimed together with its child process. Two deliberate exceptions remain: claude.ai connectors are not reclaimed merely because they are absent from the file, and if a configuration file fails to parse, that scope is excluded from reclamation for that pass — otherwise one typo could disconnect every service currently in use.
- **Fixed completed workflows becoming impossible to look up.** A background task became eligible for reclamation the instant it completed, so querying it returned “task not found”; resumed runs were unqueryable from the start because they retained the original runId but were registered under a new id. Completed runs now have a grace period and can also be queried by runId.
- **Workflow return values and completion notifications now include the full run-directory path** containing `journal.jsonl` and `state.json`. Previously they provided only a runId, leaving you to guess where the files were when diagnosing why a run returned nothing.
- **Workflow resume no longer stays silent when its cache is invalidated.** Changing the script or the question given to the agent invalidates the entire cache and falls back to a full rerun, but previously looked exactly like a successful resume while charging for the work again. It now reports which invocation first diverged, how many entries were reused and how many were discarded.
- **The 200-search-per-session limit on web search has been removed.** Its counter accumulated for the lifetime of the process and never reset, so long sessions eventually lost search entirely, with the error surfacing on an ordinary search far away from the loop that caused it. Set `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` if you want a hard limit.
- **The 200-subagent-per-session limit has also been removed** for the same reason (the session above ran 216). The concurrency limit of 20 and nesting-depth limit of 3 remain — those bound resources in simultaneous use and are released when agents finish.

## 2.33.0 - 2026-08-07

- **Added a dedicated DeepSeek search source.** DeepSeek provides server-side web search itself, but occ previously ran it under the Anthropic source name — `/search-setting` therefore showed “Connected Anthropic” while every byte went to DeepSeek, and treated the same endpoint as two providers by sending one request through each. It is now an independent source displayed under its real name. Coverage is broader too: this path no longer depends on the main loop's protocol, so sessions pinned to `OPENAI_WIRE_API=chat` — the only protocol with no built-in search at all — can still use server-side search instead of falling back to keyless scraping.
- **Search support is now probed automatically after a DeepSeek endpoint is configured.** Having a key does not mean that deployment implements the search tool: self-hosted mirrors and older gateways may accept the key but reject the tool. occ now sends a tiny request that asks whether the endpoint accepts the tool, without performing a real search; if it does not, the source is disabled and the endpoint's exact response is shown. Network instability, rate limiting and expired keys are not misclassified as “unsupported”.
- **Fixed occasional blank, unopenable entries in search results.** DeepSeek reports a failed search as an item in the result list, but occ recognized only another error shape and treated it as a real result.
- **`/search-setting` now supports disconnecting, cancelling and reprobing.** Press `D` to disconnect an authenticated search source (Gemini / Codex), `Esc` during authentication to cancel the login instead of closing the panel, and `R` to reprobe every source.
- **Fixed authenticated search sources remaining unusable.** Once a source failed in a session, it stayed disabled until restart — even after you logged in or corrected its configuration. Successful login, successful disconnect and pressing `R` now all trigger reevaluation. If a source still appears connected after disconnecting, the panel explains why (for example, `~/.codex/auth.json` belongs to Codex CLI and is not occ's to delete, or `GEMINI_API_KEY` remains in your environment).
- **Fixed `/effort` having no effect at all on Gemini and Grok.** The selected value was displayed and then discarded without ever being sent. Both providers now map it to their own parameters; Grok-4 models reject that parameter, so they no longer pretend to offer the option.
- **Fixed `/effort` disagreeing with what DeepSeek actually received.** With `deepseek-chat` / `deepseek-reasoner` — the two names DeepSeek's official documentation tells users to configure — the UI pretended there was no control while requests were still being manipulated by it. DeepSeek also has only three levels while occ has five; it silently ignored the extra two and fell back to its own default while the status line continued showing the selected level. Both DeepSeek protocol paths now collapse the levels consistently.
- **The default thinking effort for Claude-family models has increased from `high` to `xhigh`** consistently across opus / fable / sonnet / haiku. Explicit `/effort` or `modelSettings` values are unaffected.
- The web-search tool description now accurately says that one call fans out in parallel across the keyless engine pool and every authenticated official source, then merges and deduplicates the results. It needs no separate key and works on non-Anthropic endpoints too. The previous “available only in the US” wording was untrue for occ and could cause the model to avoid the tool.

## 2.32.4 - 2026-08-07

- **Fixed interactive sessions still showing `Not logged in · Please run /login` after configuring a third-party provider.** occ has an approval prompt for `ANTHROPIC_API_KEY` values found in the environment (“Detected a custom API key in your environment”), and it **defaults to “No (recommended)”**. The problem was that keys configured by occ itself were also treated as “found in the environment”: the provider key you entered in `/login` was copied into occ's internal environment, then occ asked whether to use it even though you had never had a chance to approve it. This fix was validated in a real interactive session: released version 2.32.3 showed the approval prompt and could not complete a single turn, while this version showed no prompt and completed the conversation normally, with the reply confirmed to come from `deepseek-v4-flash`.

## 2.32.3 - 2026-08-07

- **Fixed version 2.32.2 not actually resolving `Not logged in · Please run /login`.** The previous fix was attached to several known configuration entry points, but that was whack-a-mole: other code could change provider configuration mid-session without triggering DeepSeek routing's internal mirror, so requests still went to Anthropic's official endpoint without credentials. The fallback now lives at **API client construction time**: no request can be constructed from configuration whose mirror has not been applied, regardless of who changed it or when.
- This was validated end to end against the **real build artifact**, not only with unit tests: given the same input where configuration arrives mid-session, 2.32.2 returned `Not logged in`, while this version returned a normal response confirmed to use `deepseek-v4-flash`; the standard paths through both launch entry points were regression-tested as well.

## 2.32.2 - 2026-08-07

- **Fixed DeepSeek immediately reporting `Not logged in · Please run /login` after setup and displaying the model as `claude-sonnet-5`.** occ routes DeepSeek through its Anthropic-compatible endpoint, which requires an internal mirror of the configuration; that mirror, however, **ran only once at startup** and required the API key to exist at that moment. On first login there is no key during startup, so no mirror was created. Login then wrote the configuration and occ immediately believed it was using this path without actually applying it — requests went to Anthropic's official endpoint without credentials (hence the 401), and model aliases resolved to Anthropic names. The mirror is now also removed correctly when switching to another provider instead of continuing to point at DeepSeek.
- **Fixed third-party models receiving a `[1m]` suffix.** That suffix exists solely to send Anthropic's 1M-context beta header and has no meaning for other providers.
- Fixed the new “thinking effort” field in onboarding being unreachable with Enter because the save action was still attached to the preceding field.

## 2.32.0 - 2026-08-07

The per-tier model settings introduced in 2.31.0 were largely ineffective for third-party providers. This release fixes them and brings them into `/model`; DeepSeek users are affected most.

- **Fixed `/model` listing only Claude models in DeepSeek sessions**, complete with Anthropic's `$5/$25 per Mtok` pricing, even though your key could reach only api.deepseek.com. Version 2.31.0 moved DeepSeek to its Anthropic-compatible endpoint, but the code used the same test for “which protocol is in use?” and “is this Anthropic's own model catalog?”, making the latter answer change incorrectly too. `/model` now lists your configured tier models plus DeepSeek's complete catalog.
- **Fixed per-tier model settings being inert for third-party models.** Settings are keyed by tier, but requests contain the resolved model id; names such as `deepseek-v4-pro`, `glm-5.2` and `gpt-5.6-sol` contain no opus/sonnet marker, so their tier could not be recovered and every value set in `/model-settings` was **silently discarded**. occ now reverse-maps the configured `*_DEFAULT_<TIER>_MODEL` values. **If you previously set per-tier configuration and thought it had no effect, this was why; it will take effect now.**
- **Fixed 1M context settings for non-Claude models being clamped back to 200k.** Anthropic's 1M beta header is a constraint of Anthropic models, but that constraint was previously applied to every provider — preventing any provider whose 1M model was not named Claude (DeepSeek V4, GLM and others) from using its real window.
- **Thinking effort and maximum context can now be adjusted directly by tier in `/model`.** Highlight any row: `←/→` changes that tier's thinking effort, and `Space` cycles its maximum context (default → 128k → 200k → 272k → 512k → 1M). Every adjusted tier is saved, not only the row on which you finally press Enter. `Space` used to be a binary “1M on/off” toggle; it is now the full ladder for the same setting.
- **The maximum context and thinking effort selected during login are now persisted** by tier under `settings.modelSettings`. Maximum context was previously written as `CLAUDE_CODE_MAX_CONTEXT_TOKENS` — an environment variable whose priority is **higher than** per-tier configuration, so a one-time initial value from login silently overrode every later adjustment in `/model`; saving now removes it as well. Onboarding also has a new “thinking effort” field. ## 2.30.0 - 2026-08-06

A batch of real Windows failures, plus a rendering problem that affected every platform.

- **Every error opened a WSL window on Windows, and every hook failed.** One cause behind both: occ was treating `C:\Windows\System32\bash.exe` as a shell, and that is the WSL launcher. The Bash tool and the hook runner share that lookup, which is why the two symptoms arrived together. It now skips past it to find a real Git Bash.
- **Every Bash tool command reported "command not found" on Windows.** The PATH occ wrote into the shell environment was the literal five characters `$PATH`, because it ran a POSIX-only command through cmd.exe.
- **Automatic updates had never once worked on Windows, and failed silently.** `occ update`, `occ rollback` and LSP language servers could not launch npm-installed programs — on Windows those are `.cmd` wrappers that need a different launch path. The background updater also discarded its own failures, so there was no sign anything was wrong.
- **`occ bg kill` always refused to run on Windows**, reporting that it could not verify the process. The same underlying problem made Computer Use crash on its first call there.
- Fixed terminal display corruption: background colour bleeding sideways, text clipped on the left, and large blank gaps between lines. Three separate causes, two of which also affected macOS and Linux. If you have seen this, it should be gone.
- **A background agent's timer stayed at 0s** while the token counter beside it climbed. It was measuring duration with a clock that can step backwards, which Windows does routinely after resuming from sleep.
- **Hook failures now tell you which hook failed and why.** Previously you got a single line — "UserPromptSubmit hook error" — even when the hook itself had printed a full explanation.
- MCP server authentication failures no longer say just `fetch failed`; you get the actual reason (connection refused, DNS failure, certificate problem, proxy error).
- The waiting animation now fades to amber when a response is merely slow, and turns red only when nothing has come back at all. Both used to look like failure.
- Also fixed on Windows: shell completion never installed, ChatGPT credentials were written into the current project instead of your home directory, worktree directory links silently did nothing, plugin install and uninstall failed at random while antivirus held files open, and MCP server processes accumulated instead of exiting.
- Fixed SSH and Computer Use, which were broken on **every** platform — including "paste image from clipboard" on macOS.
